**`safe_tool(*, degraded: Callable[[], R])`** — the decorator from RESEARCH Pattern 8, verbatim:

```python
P = ParamSpec("P")
R = TypeVar("R")


def safe_tool(
    *, degraded: Callable[[], R]
) -> Callable[[Callable[P, Awaitable[R]]], Callable[P, Awaitable[R]]]:
    def decorate(fn: Callable[P, Awaitable[R]]) -> Callable[P, Awaitable[R]]:
        @functools.wraps(fn)
        async def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
            try:
                return await fn(*args, **kwargs)
            except Exception:  # noqa: BLE001 - see the docstring; nothing may escape
                log.exception("mcp_tool_failed", tool=fn.__name__)
                return degraded()

        return wrapper

    return decorate
```
Docstring must record the verified leak: `mcp 2.0.0`'s `Tool.run` wraps any escaping exception as
`ToolError(f"Error executing tool {name}: {e}")` and `MCPServer._handle_call_tool` returns
`CallToolResult(content=[TextContent(text=str(e))], is_error=True)` -- VERBATIM. An asyncpg
connection error carries the full DSN (user, password, host, port, database), and structlog's
three-layer redaction does not touch this channel because it is not a log record. Also record that
`functools.wraps` is load-bearing (the SDK reads `fn.__doc__`, the return annotation and
`inspect.signature`, which follows `__wrapped__`), and that plan 06-09's
`test_decorated_tools_still_publish_schemas` is what proves it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude → MCP tool arguments | Untrusted model-chosen scalars (`weeks`, exercise `name`) cross here |
| MCP tool → PostgreSQL | Every tool query crosses here inside a transaction whose write capability is the control |
| Tool body exception → Claude | `mcp 2.0.0` returns `str(e)` verbatim to the model; structlog does not see this channel |
