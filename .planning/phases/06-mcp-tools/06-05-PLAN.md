**`roll_up_muscles`** — pure, synchronous, no session, so it is unit-testable with no container:

```python
def roll_up_muscles(
    volume: MuscleGroupVolumeResult, frequency: TrainingFrequencyResult
) -> list[MuscleGroupRollup]:
    """Fold a per-week x per-muscle grid into ONE row per canonical muscle group.

    Returns exactly 19 rows, one per `CanonicalMuscleGroup`, sorted by `.value` -- an untrained
    group is a ZERO row, never an absence. Both source results omit untrained groups entirely,
    and an omitted group is indistinguishable from a group the caller forgot to ask about. A zero
    row is the most diagnostically interesting row for "which muscles are undertrained?", which is
    the entire question this tool exists to answer.

    Set counts are SUMMED across weeks -- sets are additive. `sessions` and `sessions_per_week`
    are NOT summed: they are taken from `frequency`, which de-duplicates workouts across the whole
    window. `frequency.py`'s module docstring records what summing them instead did on real data:
    14 of 16 muscle groups inflated by up to 4.0x, every inflated figure still reading as
    plausible training history.
    """
```
Implementation: accumulate `direct_sets`, `indirect_sets` (ints) and `weighted_sets` (`Decimal`,
starting at `Decimal("0")` — never `0.0`) into a `dict[CanonicalMuscleGroup, ...]` over
`volume.weeks[*].muscle_groups`; build a `dict[CanonicalMuscleGroup, MuscleGroupFrequency]` from
`frequency.muscle_groups`; then emit one `MuscleGroupRollup` for every member of
`sorted(CanonicalMuscleGroup, key=lambda g: g.value)`, defaulting missing frequency entries to
`sessions=0`, `sessions_per_week=Decimal("0")`, `insufficient_data=True` (zero sessions IS
insufficient — `metadata.is_insufficient(0)` is `True`, and defaulting to `False` would let an
untrained muscle read as a confident zero).

def _degraded_weekly() -> WeeklyVolumeResponse:
    return WeeklyVolumeResponse(data_available=False, volume=None)


@safe_tool(degraded=_degraded_weekly)
async def fitness_get_weekly_volume(
    ctx: Context[AppContext],
    weeks: Annotated[
        int,
        Field(ge=1, le=MAX_WEEKS, description="Whole weeks back from today, ending today. Max 52."),
    ] = 12,
) -> WeeklyVolumeResponse:
    """Weekly training volume for the last N weeks: sessions, hard sets, total reps and tonnage
    per Monday-start week. Warm-up sets are excluded from every figure, and tonnage is reported
    only for sets that carry both a weight and a rep count.

    user_id = resolve_user_id(ctx)
    async with read_only_session(ctx) as session:
        start_day, end_day = await window_from_weeks(session, user_id=user_id, weeks=weeks)
        volume = await get_weekly_volume(
            session, user_id=user_id, start_day=start_day, end_day=end_day
        )
    return WeeklyVolumeResponse(data_available=True, volume=volume)

    ctx: Context[AppContext],

        int,
        Field(ge=1, le=MAX_WEEKS, description="Whole weeks back from today, ending today. Max 52."),
    ] = 12,
) -> MuscleGroupVolumeResponse:
    """Per-muscle-group training volume over the last N weeks: direct sets, indirect sets, the
    weighted total, and how often each group was trained. Always returns all 19 canonical muscle
    groups, including the ones you did not train -- a zero row is the answer to "which muscles are

    on the wire; the rollup is ~7,851 bytes at any window. Week-by-week TOTAL volume is available
    from `fitness_get_weekly_volume`, and muscle-level movement between two blocks from
    `fitness_compare_periods`.
    """
