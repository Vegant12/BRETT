```python
def _degraded_progression() -> ExerciseProgressionResponse:
    return ExerciseProgressionResponse(
        data_available=False, requested_name="", matched=False, candidates=[],
        progression=None, points_truncated=False, total_points=0,
    )


@safe_tool(degraded=_degraded_progression)
async def fitness_get_exercise_progression(
    ctx: Context[AppContext],
    exercise_name: Annotated[
        str,
        Field(
            min_length=1,
            max_length=255,
            description="The exercise name as it appears in Hevy, e.g. 'Bench Press (Barbell)'.",
        ),
    ],
    weeks: Annotated[
        int,
        Field(ge=1, le=MAX_WEEKS, description="Whole weeks back from today, ending today. Max 52."),
    ] = 12,
) -> ExerciseProgressionResponse:
    """One exercise's progression over the last N weeks: per training day, the sets, reps, volume,
    best weight, best reps and an estimated 1RM where the modality and rep range make one
    meaningful.

    Give the exercise by NAME. If the name matches no exercise, or more than one, no analytics are
    computed and `candidates` lists what was found so you can ask again with an exact name.
    """
```
Body:
1. `user_id = resolve_user_id(ctx)`; open `read_only_session`.
2. `matches = await find_templates_by_title(session, user_id=user_id, name=exercise_name)`.
3. If `len(matches) != 1`: return
   `ExerciseProgressionResponse(data_available=True, requested_name=exercise_name, matched=False,
   candidates=[ExerciseCandidate(title=t, exercise_template_external_id=x) for t, x in matches],
   progression=None, points_truncated=False, total_points=0)`. Zero matches gives an empty
   `candidates`; two or more gives them all. Both are ordinary successful results — `is_error`
   stays false. Add the comment: `matched=False` + empty candidates means "no such exercise";
   `matched=False` + two or more means "be more specific".
4. Otherwise `_title, external_id = matches[0]`; `start_day, end_day = await window_from_weeks(...)`;
   `result = await get_exercise_progression(session, user_id=user_id,
   exercise_template_external_id=external_id, start_day=start_day, end_day=end_day)`.
5. Truncate the series to the MOST RECENT `MAX_PROGRESSION_POINTS`:
   `total_points = len(result.points)`; `points_truncated = total_points >
   MAX_PROGRESSION_POINTS`; `kept = result.points[-MAX_PROGRESSION_POINTS:]`;
   `progression = result.model_copy(update={"points": kept})`. Comment: the tail, not the head —
   "am I progressing?" is a question about recent sessions, and `model_copy` is used rather than
   rebuilding the model so a future field added to `ExerciseProgressionResult` cannot be silently
   dropped here.
6. Return with `data_available=True, matched=True, candidates=[]`.

```python
async def fitness_get_plateaus(
    ctx: Context[AppContext],
    lookback_weeks: Annotated[
        int,
        Field(ge=1, le=MAX_WEEKS, description="Weeks of history to judge against. Max 52."),
    ] = DEFAULT_PLATEAU_LOOKBACK_WEEKS,

        bool,
        Field(description="Return only exercises judged plateaued. Set false to see every one."),
    ] = True,
) -> PlateauResponse:

    minimum-session and minimum-elapsed-day rules each verdict was reached under.
    """
```
Body: `resolve_user_id`; `read_only_session`; `report = await get_plateaus(session,
user_id=user_id, lookback_weeks=lookback_weeks)`. D-05: this tool keeps the analytics function's

exercises_truncated=exercises_truncated, total_exercises=total_exercises,
coverage=report.coverage, freshness=report.freshness)`.

Note in a comment: `total_exercises` counts the FILTERED candidate set, not the whole report, so

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude → `exercise_name` | A free-text string that reaches a SQL comparison — the highest-risk argument in the phase |
| Claude → `lookback_weeks` / `weeks` / `plateaued_only` | Bounded scalars validated by the published schema |
| Tool exception → Claude | `safe_tool` is the only guard on this channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-04 | Tampering | SQL injection via `exercise_name` | mitigate | `find_templates_by_title` compares `func.lower(ExerciseTemplate.title) == name.strip().lower()` — a bound parameter, never an f-string. `Field(max_length=255)` matches the column and rejects longer input before any query. Ruff `S608` enabled; no `text(` in either module |
| T-06-02 | Elevation of Privilege | resolving a name to another user's template | mitigate | `find_templates_by_title` filters on `user_id` AND `provider`, not on title alone; `user_id` is resolved server-side and is not a tool parameter |
| T-06-12 | Spoofing (answer integrity) | silently answering about the wrong exercise when a name matches two templates | mitigate | D-02: `len(matches) != 1` short-circuits with `matched=False` and the full candidate list. Live data makes this real — `exercise_templates.title` carries no uniqueness constraint and Hevy ships both built-in and user-custom templates under the same title |
| T-06-01 | Information Disclosure | `get_plateaus` raising `ValueError("lookback_weeks must be positive")`, or an asyncpg error carrying the DSN | mitigate | `Field(ge=1)` makes the analytics guard unreachable from MCP; `@safe_tool` catches anything else and returns a degraded payload |
| T-06-03 | Tampering | a write reaching the database | mitigate | `read_only_session` (`postgresql_readonly=True`); no write construct imported in either module |
| T-06-05 | Denial of Service | a 52-week progression series (104 points, 25 KB structured / 60 KB wire) or a 40-exercise plateau report (16 KB / 37 KB) | mitigate | `MAX_PROGRESSION_POINTS = 60` tail-truncation and `MAX_PLATEAU_EXERCISES = 30`, both with `*_truncated` + `total_*`. Budgets 24 KB each enforced in plan 06-10 |
| T-06-11 | Tampering (integrity) | a truncated list read as complete | mitigate | `points_truncated`/`total_points` and `exercises_truncated`/`total_exercises` are required response fields |
| T-06-08 | Information Disclosure (low) | SDK validation error echoing a rejected `exercise_name` | accept | The echoed value is the model's own argument. Parameters stay scalar; no pass-through object is accepted |
</threat_model>
