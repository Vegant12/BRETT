**Module constants**
```python
DENY_KEYS = frozenset({
    "api_key", "apikey", "hevy_api_key", "authorization", "auth", "password", "passwd",
    "secret", "mcp_auth_secret", "jwt_secret", "token", "access_token", "refresh_token",
    "database_url", "db_url", "dsn", "credentials", "encrypted_credentials", "cookie",
    "set-cookie", "x-api-key",
})
REDACTED = "***REDACTED***"
```

**Layer 2 — `censor_keys(_logger, _name, event_dict)`**: for each key in `list(event_dict)`,
if `k.lower() in DENY_KEYS`, set the value to `REDACTED`.

**Correlation bridge — `add_correlation_id(_logger, _name, event_dict)`**: read
`asgi_correlation_id.correlation_id.get()`; if not None, set `event_dict["correlation_id"]`.
This is REQUIRED as a separate processor — `structlog.contextvars.merge_contextvars` does NOT
see asgi-correlation-id's ContextVar (RESEARCH Pitfall 7, reproduced live).

**Layer 3 — `make_value_scrubber(secrets: list[str])`**: returns a processor that recursively
walks the event dict (str / dict / list / tuple, preserving container type) and for each `str`
replaces every occurrence of every secret in `secrets` with `REDACTED`. The `secrets` list
arrives longest-first from `settings.secret_values()`, which matters when one secret is a
substring of another (the DB URL contains the password).

**The shared chain — ORDER IS LOAD-BEARING:**
```python
shared = [
    structlog.contextvars.merge_contextvars,
    add_correlation_id,
    structlog.stdlib.add_log_level,
    structlog.stdlib.add_logger_name,
    structlog.processors.TimeStamper(fmt="iso", utc=True),
    censor_keys,                                     # layer 2
    structlog.processors.StackInfoRenderer(),
    structlog.dev.set_exc_info,
    structlog.processors.format_exc_info,            # exc_info tuple -> str
    make_value_scrubber(settings.secret_values()),   # layer 3 — MUST be after format_exc_info
]
```
If layer 3 runs before `format_exc_info`, the traceback is still an `exc_info` tuple and the
string scrubber sees nothing — that is leak channel (b).

**structlog.configure**: `processors=[*shared, structlog.stdlib.ProcessorFormatter.wrap_for_formatter]`,
`logger_factory=structlog.stdlib.LoggerFactory()`, `wrapper_class=structlog.stdlib.BoundLogger`,
`cache_logger_on_first_use=True`.

**D-06 renderer split** — cosmetic only, applied after the shared chain:
```python
dev = settings.environment == "development"
renderer = structlog.dev.ConsoleRenderer(colors=True) if dev else structlog.processors.JSONRenderer()
```

**ProcessorFormatter** — this is what covers third-party loggers (leak channel (c)):
```python
formatter = structlog.stdlib.ProcessorFormatter(
    foreign_pre_chain=shared,
    processors=[structlog.stdlib.ProcessorFormatter.remove_processors_meta, renderer],
)
handler = logging.StreamHandler(sys.stdout)
handler.setFormatter(formatter)
root = logging.getLogger()
root.handlers = [handler]
root.setLevel(settings.log_level.upper())

for noisy in ("uvicorn", "uvicorn.error", "uvicorn.access", "sqlalchemy.engine", "alembic"):
    logging.getLogger(noisy).handlers = []
    logging.getLogger(noisy).propagate = True
```

Type-annotate every function (`disallow_untyped_defs = true` is on). Use
`from typing import Any` for the processor `event_dict: dict[str, Any]` params.

```python
from contextlib import asynccontextmanager
from collections.abc import AsyncIterator

import structlog
from asgi_correlation_id import CorrelationIdMiddleware, correlation_id
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse

from app.config import get_settings
from app.logging import configure_logging

settings = get_settings()      # fail-fast BEFORE anything else
configure_logging(settings)    # then logging, so the scrubber has the secret values
log = structlog.get_logger()


@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    log.info("service_starting", environment=settings.environment)
    try:
        yield
    finally:
        log.info("service_stopped")


app = FastAPI(title="BRETT", lifespan=lifespan)
app.add_middleware(CorrelationIdMiddleware)


# D-05: identical behavior in EVERY environment. No traceback ever reaches the client.
@app.exception_handler(Exception)
async def unhandled_exception_handler(request: Request, exc: Exception) -> JSONResponse:
    log.exception("unhandled_error", path=request.url.path, method=request.method)
    return JSONResponse(
        status_code=500,
        content={"error": "internal server error", "correlation_id": correlation_id.get()},
    )
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process internals → stdout log stream | Every log record, including ones emitted by libraries nobody in this repo wrote |
| unhandled exception → HTTP response | Default framework behavior would serialize the exception detail to the client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-07 | Information Disclosure | secret inside an arbitrary log field value | mitigate | Layer 3 `make_value_scrubber(settings.secret_values())` recursive string replace; asserted in `test_secret_never_appears_in_logs_or_response` |
| T-01-08 | Information Disclosure | secret inside a rendered exception traceback | mitigate | Layer 3 positioned strictly AFTER `structlog.processors.format_exc_info` in the shared chain |
| T-01-09 | Information Disclosure | third-party stdlib loggers (uvicorn, sqlalchemy, alembic) bypassing structlog | mitigate | `ProcessorFormatter(foreign_pre_chain=shared)` + root handler replacement + `propagate=True` on named noisy loggers |
| T-01-10 | Information Disclosure | traceback in the HTTP 500 body | mitigate | D-05 `@app.exception_handler(Exception)` returning a fixed `{error, correlation_id}` body with no environment branch; `debug=True` never set |
| T-01-11 | Repudiation | sanitized errors become undebuggable | mitigate | `add_correlation_id` processor bridges asgi-correlation-id's ContextVar into every log line; the same id is returned to the client |
| T-01-12 | Information Disclosure | a secret not present in `secret_values()` (e.g. a value read directly from `os.environ`) | accept | Layer 2 deny-list covers common key names; the project rule is that all config flows through `Settings`. Re-evaluate in Phase 3 when the Hevy key is actually used |
</threat_model>
