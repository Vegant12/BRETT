```python
import structlog
from fastapi import APIRouter, Request
from fastapi.responses import JSONResponse
from sqlalchemy import text

router = APIRouter(tags=["health"])
log = structlog.get_logger()


@router.get("/health")
async def health(request: Request) -> JSONResponse:
    """D-03: minimal body {status, database}. D-04: open — no auth.
    Render's platform health check and uptime monitors must reach this without a token."""
    database = "connected"
    status_code = 200
    try:
        async with request.app.state.engine.connect() as conn:
            await conn.execute(text("SELECT 1"))
    except Exception:
        # Log the detail; return only the coarse state (D-03/D-05).
        log.exception("health_db_check_failed")
        database, status_code = "error", 503
    return JSONResponse(
        status_code=status_code,
        content={"status": "ok" if status_code == 200 else "degraded", "database": database},
    )
```

   Do NOT add alembic revision, environment name, uptime, version, hostname, or any part of the
   DSN to the response body — D-03 is explicit and an open endpoint must disclose nothing.
   Do NOT add an auth dependency (D-04).
   Do NOT narrow the `except` clause — any failure to reach the DB must degrade, not 500.

   shared session engine — that would poison the rest of the session-scoped suite. Instead
   swap `app.state.engine` for a throwaway engine pointed at a closed port, with a short
   connect timeout so the test stays fast, then restore the original in a `finally`:
   ```python
   from sqlalchemy.ext.asyncio import create_async_engine

   @pytest.mark.integration
   def test_health_reports_db_error(client):
       app = client.app
       original = app.state.engine
       dead = create_async_engine(
           "postgresql+asyncpg://nobody:nopass@127.0.0.1:1/nodb",
           connect_args={"timeout": 1},
           pool_pre_ping=False,
       )
       app.state.engine = dead
       try:
           r = client.get("/health")
           assert r.status_code == 503
           assert r.json() == {"status": "degraded", "database": "error"}
           for leak in ("nobody", "nopass", "127.0.0.1", "asyncpg", "Traceback"):
               assert leak not in r.text, f"FOUND-05/D-03 violated: {leak!r} in /health body"
       finally:
           app.state.engine = original
   ```
   Port 1 is reserved and never listening; combined with `timeout: 1` the failure is immediate
   and deterministic. If the connection somehow hangs on the CI/dev machine, lower the timeout
   rather than switching to a mock — the point of this test is that a REAL failed connection
   degrades cleanly.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → `GET /health` | The only unauthenticated endpoint in the system; reachable by anyone once deployed in Phase 2 |
| database failure → HTTP response | Connection errors carry the DSN, host, and driver internals |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-23 | Information Disclosure | `/health` response body | mitigate | D-03 restricts the body to `{status, database}` — no version, revision, env name, hostname, or DSN; asserted by the leak-substring loop in `test_health_reports_db_error` |
| T-01-24 | Information Disclosure | DB connection error text reaching the client | mitigate | The `except` block logs via `log.exception` (which passes through the Plan 02 redaction chain) and returns only the literal `"error"` |
| T-01-25 | Spoofing | unauthenticated `/health` access | accept | D-04: deliberately open so Render health checks and uptime monitors work; the body contains nothing sensitive. Re-evaluate only if the body ever grows |
| T-01-26 | Denial of Service | `/health` opening a new connection per request | mitigate | `pool_pre_ping=True` + a bounded pool (`pool_size=5, max_overflow=5`) from `make_engine`; a single-user personal deployment has negligible health-check volume. Rate limiting arrives in Phase 7 (DEPLOY-03) |
| T-01-27 | Availability | engine leaked across restarts / event loops | mitigate | Engine created in `lifespan` and `await engine.dispose()` in the `finally` branch; never a module-level global |
