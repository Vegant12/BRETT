## Pattern Assignments

### `backend/app/config.py` (config, env → typed transform)

**Analog:** none. **Source:** `01-RESEARCH.md` Pattern 6, Layer 1 (lines ~657–727) — copy verbatim as the starting point.

Non-negotiable elements, each tied to a verified finding:

- `SettingsConfigDict(env_file=".env", extra="ignore", frozen=True)`
- `database_url: SecretStr` — **not** `PostgresDsn`. Pitfall 2(d) proved `PostgresDsn` echoes the raw URL (password included) into the `ValidationError` message.
- Validators re-raise with `from None` and never interpolate the input value.
- `async_database_url` property normalizes: force `postgresql+asyncpg`, translate `sslmode` → `ssl`, drop `channel_binding`. Pitfall 3: `asyncpg.connect()` has no `sslmode` param and no `**kwargs` — guaranteed `TypeError` otherwise.
- `secret_values() -> list[str]` returning **longest-first** — this is the input to the logging scrubber, and it must also emit the DB URL's password component separately.
- `@lru_cache def get_settings()` — tests call `get_settings.cache_clear()`.

**Build-order dependency:** config must be constructed *before* `configure_logging`, because the scrubber consumes `settings.secret_values()`.

---

### `backend/app/logging.py` (utility, event-dict transform)

**Analog:** none. **Source:** `01-RESEARCH.md` Pattern 6, Layers 2+3 (lines ~734–835).

Three layers; RESEARCH proved each one alone leaks:

| Layer | Mechanism | Leak it closes |
|-------|-----------|----------------|
| 1 | `SecretStr` in config | Pydantic `ValidationError` echoing input; config `repr`/`model_dump` |
| 2 | `censor_keys` deny-list processor | secret under a known key name (`api_key`, `authorization`, …) |
| 3 | `make_value_scrubber(settings.secret_values())` | secret inside an arbitrary value **and inside a rendered traceback** |

Ordering constraints that are load-bearing:

- Layer 3 must sit **after** `structlog.processors.format_exc_info` in the chain — otherwise the traceback is still an exc_info tuple and the string scrubber sees nothing.
- The whole shared chain must be passed as `ProcessorFormatter(foreign_pre_chain=shared, ...)`, and the root logger's handlers replaced, or uvicorn/sqlalchemy/alembic stdlib records bypass redaction entirely (Pitfall 2c).
- `add_correlation_id` must be an explicit processor. `merge_contextvars` does **not** see `asgi-correlation-id`'s ContextVar (Pitfall 7).
- D-06 renderer split (`ConsoleRenderer` when `environment == "development"`, else `JSONRenderer`) is applied *after* the shared chain, so it cannot affect safety.

### `backend/app/core/time.py` (utility, instant → local bucket)

**Analog:** none. **Source:** `01-RESEARCH.md` Pattern 5 (lines ~594–636).

Copy `utc_now`, `_require_aware`, `to_local`, `local_day`, `local_week_start`, `local_day_bounds`.

Key points:
- `_require_aware` raises `ValueError` on naive input — FOUND-04 enforced by guard, not convention.
- `local_day_bounds` returns a half-open UTC range for **filtering**; `AT TIME ZONE` is for `GROUP BY`/`SELECT` only (wrapping the column in `WHERE` kills the index).
- `tz` is always a parameter, never a module constant — FOUND-03 requires the value come from `users.timezone`.

Verified boundary table to encode as test parameters: `16:30Z → 08-23`, `17:00Z → 08-24`, `23:30Z → 08-24`, `00:30Z(+1d) → 08-24`.

### `backend/app/main.py` + `backend/app/api/routes/health.py` (controller, request-response)

**Analog:** none. **Source:** `01-RESEARCH.md` Pattern 4 (lines ~502–573).

`main.py` bootstrap order is load-bearing: `get_settings()` → `configure_logging(settings)` → `structlog.get_logger()` → `lifespan` creating the engine → `FastAPI(...)` → `add_middleware(CorrelationIdMiddleware)` → routers → `@app.exception_handler(Exception)`.

- Engine is created in `lifespan`, never at module import (wrong event loop under pytest-asyncio).
- `CorrelationIdMiddleware` is pure-ASGI, so `correlation_id.get()` still resolves inside the exception handler — verified. A hand-rolled `BaseHTTPMiddleware` would not.
- D-05 handler returns exactly `{"error": "internal server error", "correlation_id": ...}` with status 500 in **every** environment. No `debug=True`, ever.
- `/health` (D-03/D-04): open, `SELECT 1` via `request.app.state.engine.connect()`, returns `{status, database}` — 200/`connected` or 503/`degraded`+`error`. The exception detail goes to the log, never the body.
- Never mount `alembic upgrade head` in `lifespan` — migrations run out-of-band.

## Shared Patterns

Cross-cutting rules that apply across multiple files. These replace the usual "copy from `src/...`" excerpts, since no source exists.

### Secret handling (applies to: config.py, logging.py, main.py, alembic.ini, .env.example, .gitignore, all tests)
Three-layer defense, all layers required. `SecretStr` in config, `censor_keys` on key names, value-scrubber after `format_exc_info`, `foreign_pre_chain` covering third-party loggers, sanitized HTTP error body. `alembic.ini` and `.env.example` carry names only. `gitleaks`/`detect-secrets` in pre-commit.

### Timestamps (applies to: db/base.py, all models, all future models)
`DateTime(timezone=True)` exclusively. `app.core.time.utc_now()` is the only sanctioned "now". Consider enabling Ruff `DTZ` rules to ban `datetime.utcnow()` / naive `datetime.now()` mechanically.

### Timezone source (applies to: core/time.py, all consumers)
`users.timezone` is the source of truth. Not an env var, not a constant. Every helper takes `tz: str` as a parameter.

### SQL construction (applies to: health.py, migrations, tests)
SQLAlchemy constructs or `sa.text(...).bindparams(...)` only. Never f-string SQL. Ruff `S608` enforces.

### Engine lifecycle (applies to: db/session.py, main.py, conftest.py)
One engine per lifespan/fixture scope, `pool_pre_ping=True`, `echo=False`, disposed on exit. Never a module-level global engine.

### Migrations authority (applies to: migrations/, conftest.py, main.py)
Alembic is the only thing that creates schema. `create_all()` appears nowhere. Migrations never run at app startup.
