**Builder class.** A plain class holding the session, with four async methods. It never commits.

```python
class GoldenBuilder:
    """Builds synthetic analytics fixtures with exact, hand-computable contents.

    Writes with explicit Core statements, mirroring `app/integrations/hevy/workouts.py`, and
    FLUSHES rather than commits. The analytics function under test receives the SAME
    `AsyncSession`, so it sees the flushed rows inside the open transaction -- which is why
    every analytics function takes `session: AsyncSession` and not an `async_sessionmaker`.
    A function that opened its own session would run in a different transaction and see none
    of this.
    """

    def __init__(self, session: AsyncSession) -> None:
        self._session = session
        self._workout_seq = 0

    async def user(
        self, *, user_id: uuid.UUID, timezone: str = "Asia/Jakarta"
    ) -> uuid.UUID: ...

    async def template(
        self,
        *,
        external_id: str,
        exercise_type: str = "weight_reps",
        title: str | None = None,
        muscles: Sequence[tuple[CanonicalMuscleGroup, MuscleRole]] = (),
        user_id: uuid.UUID = DEFAULT_USER_ID,
    ) -> str: ...

    async def override(
        self,
        *,
        external_id: str,
        muscles: Sequence[tuple[CanonicalMuscleGroup, MuscleRole]],
        user_id: uuid.UUID = DEFAULT_USER_ID,
    ) -> int: ...

    async def workout(
        self,
        *,
        start_time: dt.datetime,
        exercises: Sequence[GoldenExercise],
        user_id: uuid.UUID = DEFAULT_USER_ID,
        title: str = "Fixture Workout",
        external_id: str | None = None,
        duration_minutes: int = 60,
    ) -> uuid.UUID: ...
```

Method bodies, concretely:

- `user()` — `insert(User)` with `{"id": user_id, "timezone": timezone}`, then
  `await self._session.flush()`, return `user_id`. Guard: if `user_id == DEFAULT_USER_ID`,
  raise `ValueError("the seeded default user already exists")` — migration 0002 seeds it and a
  second insert would violate the primary key.

- `template()` — one `insert(ExerciseTemplate)` with
  `{"id": uuid.uuid4(), "user_id": user_id, "provider": "hevy", "external_id": external_id,
  "title": title or external_id, "exercise_type": exercise_type,
  "primary_muscle_group": None, "secondary_muscle_groups": [], "equipment_category": None,
  "is_custom": False}`. Then, if `muscles` is non-empty, one executemany
  `insert(ExerciseMuscle)` with one dict per pair:
  `{"id": uuid.uuid4(), "user_id": user_id, "exercise_template_external_id": external_id,
  "muscle_group": muscle_group.value, "role": role.value, "source": MappingSource.CURATED.value}`.
  Then `await self._session.flush()`; return `external_id`.
  Store `.value` (the string), never the enum object — the columns are `String`.

- `override()` — delegate: `return await set_override(self._session, user_id=user_id,
  template_external_id=external_id, assignments=list(muscles), note="analytics fixture")`,
  then `await self._session.flush()`. Do NOT insert `ExerciseMuscleOverride` rows by hand:
  the delete-then-insert replacement semantics must have exactly one implementation, and a
  second copy here is how the fixture and the resolver would eventually disagree.

- `workout()` — `_require_aware`-equivalent guard first: if `start_time.tzinfo is None`, raise
  `ValueError("naive start_time rejected: fixtures must be timezone-aware UTC")` (Ruff `DTZ`
  and FOUND-04). Then:
  - `self._workout_seq += 1`; `workout_id = uuid.uuid4()`;
    `resolved_external_id = external_id or f"{ANALYTICS_ID_PREFIX}-W{self._workout_seq:03d}"`
  - one `insert(Workout)` with `{"id": workout_id, "user_id": user_id, "provider": "hevy",
    "external_id": resolved_external_id, "title": title, "description": None,
    "routine_external_id": None, "start_time": start_time,
    "end_time": start_time + dt.timedelta(minutes=duration_minutes),
    "provider_created_at": start_time, "provider_updated_at": start_time}`
  - for each `(exercise_index, exercise)` in `enumerate(exercises)`: one `insert(WorkoutExercise)`
    with a fresh `uuid.uuid4()`, `workout_id`, `exercise_index`, `title=exercise.title`,
    `notes=None`, `exercise_template_external_id=exercise.template_external_id`,
    `supersets_id=exercise.supersets_id`; then, if the exercise has sets, ONE executemany
    `insert(WorkoutSet)` with `{"id": uuid.uuid4(), "workout_exercise_id": exercise_id,
    "set_index": set_index, "set_type": s.set_type, "weight_kg": s.weight_kg, "reps": s.reps,
    "distance_meters": s.distance_meters, "duration_seconds": s.duration_seconds,
    "rpe": s.rpe, "custom_metric": None}` for each `(set_index, s)` in `enumerate(exercise.sets)`
  - `await self._session.flush()`; return `workout_id`

**The fixture itself:**

```python
@pytest_asyncio.fixture
async def golden_workout(session: AsyncSession) -> AsyncIterator[GoldenBuilder]:
    """A builder whose every write is rolled back, pass or fail.

    Rollback rather than a compensating DELETE for two reasons, both verified in this suite:
    it survives an assertion failure mid-test, and `test_migrations.py` asserts `count(*) == 1`
    on `users` from a SEPARATE connection, which cannot see uncommitted rows at all.
    """
    try:
        yield GoldenBuilder(session)
    finally:
        await session.rollback()
```
