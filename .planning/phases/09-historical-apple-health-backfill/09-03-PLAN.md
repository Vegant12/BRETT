**(c) `_upsert_many`** — one multi-row statement per chunk. It must set **exactly** the same four
columns on conflict that `upsert_health_metric` sets (`value`, `units`, `sample_count`,
`updated_at`) or the backfill and the webhook diverge on a re-write:

```python
async def _upsert_many(
    session: AsyncSession, *, user_id: uuid.UUID, rows: Sequence[NormalizedRow]
) -> None:
    """One `INSERT ... ON CONFLICT DO UPDATE` for a whole chunk.

    `user_id` is keyword-only with no default (ASVS V4), exactly as `upsert_health_metric`
    declares it: the schema is multi-user-ready, and `export.xml` cannot supply a user id and
    must not be able to. It is resolved from the CLI argument, server-side, never from the file.

    The conflict clause is bound to the constraint BY NAME, and sets the SAME FOUR COLUMNS
    `ingest.upsert_health_metric` sets. Any divergence here means a day written by the backfill
    and re-written by the webhook ends up shaped differently from one written by the webhook
    twice.
    """
    statement = pg_insert(HealthDailyMetric).values(
        [
            {
                "id": uuid.uuid4(),
                "user_id": user_id,
                "source": SOURCE_APPLE_HEALTH,
                "metric": row.metric,
                "source_name": row.source_name,
                "local_day": row.local_day,
                "value": row.value,
                "units": row.units,
                "sample_count": row.sample_count,
            }
            for row in rows
        ]
    )
    statement = statement.on_conflict_do_update(
        constraint=_CONFLICT_CONSTRAINT,
        set_={
            "value": statement.excluded.value,
            "units": statement.excluded.units,
            "sample_count": statement.excluded.sample_count,
            "updated_at": func.now(),
        },
    )
    await session.execute(statement)
```

`app.integrations.health_auto_export.ingest`. Do **not** re-declare the constraint string; that is

**(d) `_write_rows`** — the hybrid loop. Chunk from `scan.normalized.rows` and from nothing else
(Pitfall 5: concatenating two `NormalizeResult`s would reintroduce duplicate conflict keys and
raise `CardinalityViolationError`):

```python
async def _write_rows(
    session: AsyncSession, *, user_id: uuid.UUID, rows: Sequence[NormalizedRow]
) -> tuple[int, int]:
    """Returns (written, skipped). Never commits -- the caller owns the transaction."""
    written = 0
    skipped = 0
    for start in range(0, len(rows), _CHUNK):
        chunk = rows[start : start + _CHUNK]
        try:
            async with session.begin_nested():
                await _upsert_many(session, user_id=user_id, rows=chunk)
        except SQLAlchemyError:
            # Fall back to `ingest.py`'s exact per-row path for THIS chunk only, so one bad row
            # costs 500 fast rows' worth of retries and never the whole run (D-07). The value
            # audit found zero malformed values in the real file: this arm exists for the
            # guarantee, not for expected traffic.
            for row in chunk:
                try:
                    async with session.begin_nested():
                        await upsert_health_metric(session, user_id=user_id, row=row)
                except SQLAlchemyError as exc:
                    skipped += 1
                    # Class name only: `str(DataError)` renders the bound parameters, which
                    # here are this person's calorie counts (T-08-39).
                    log.warning(
                        "health_backfill_row_skipped",
                        metric=row.metric,
                        local_day=row.local_day.isoformat(),
                        source_name=row.source_name,
                        reason=type(exc).__name__,
                    )
                else:
                    written += 1
        else:
            written += len(chunk)
        if written and written % _HEARTBEAT_ROWS < _CHUNK:
            log.info("health_backfill_progress", rows_written=written, rows_total=len(rows))
    return written, skipped
```

Keep the heartbeat a `log.info` and not a `print`: PATTERNS Shared Pattern 7 — `print` is the answer
to a question somebody asked (the D-06 summary), `log.*` is the record of what the process did. The
line still appears on the operator's terminal because `configure_logging` installs a root
`StreamHandler` on stdout, which is what D-05 asks for.

Body, in this order:

1. `async with sessionmaker() as session:` → `tz = await _user_timezone(session, user_id=user_id)`.
   Read the zone BEFORE anything else and outside the write try-block, for `ingest_payload`'s
   stated reason: an unknown user is a caller bug, not a failed sync.
2. `scan = scan_export(path, tz=tz)` — synchronous, pure, complete before the first write. This is
   what makes replace semantics unconditionally correct.
3. Derive `rows_by_metric` (a `Counter` over `row.metric`), `first_day` and `last_day` (min/max of
   `row.local_day`, `None` when there are no rows).
4. **Dry-run gate**, before any write:
   ```python
   if dry_run:
       log.info("health_backfill_dry_run", rows_would_write=len(scan.normalized.rows))
       return BackfillSummary(..., dry_run=True, rows_written=len(scan.normalized.rows),
                              rows_skipped=0, resources_advanced=())
   ```
   A dry run must not advance `sync_state` (RESEARCH Open Question 4): `complete_sync` sets
   `last_synced_at = now`, and a dry run that freshened Apple Health would claim data is present
   that was never written.
5. Real run, inside the same session and one transaction:
   - `written, skipped = await _write_rows(session, user_id=user_id, rows=scan.normalized.rows)`
   - freshness, copied from `ingest_payload` lines 270-288: one `utc_now()` for every resource, so
     activity and nutrition cannot report fractionally different ages; `ensure_sync_state` then
     `complete_sync` for each `kind` in `sorted(scan.normalized.kinds_present)`, mapped through
     `_KIND_TO_RESOURCE`. **Advance only when `written > 0`** — a run that wrote nothing has no
     claim to make. Record what was advanced in `resources_advanced`.
   - `await session.commit()`
   - On `SQLAlchemyError`, mirror `ingest_payload`'s failure branch: open a FRESH session (the one
     that raised is in an aborted transaction), `record_sync_error` for each kind, commit that,
     `log.warning("health_backfill_failed", kinds=..., reason=type(exc).__name__)`, and re-raise.
6. Completion log, mirroring `health_ingest_completed`'s shape:
   `log.info("health_backfill_completed", rows_written=..., rows_skipped=...,
   datapoints_seen=..., datapoints_dropped=..., records_total=..., kinds=...)`.
7. Return the `BackfillSummary`.
