**Auth Verification Matrix — host-agnostic, verbatim from RESEARCH.md.** `$HOST` is the Cloud Run
hostname.

```bash
HOST=<the Cloud Run hostname>
URL="https://$HOST/mcp"

# The 2026-07-28 per-request envelope. Omitting _meta yields -32602, not an auth error.
BODY='{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{"_meta":{
  "io.modelcontextprotocol/protocolVersion":"2026-07-28",
  "io.modelcontextprotocol/clientCapabilities":{}}}}'

HDRS=(-H "Content-Type: application/json"
      -H "Accept: application/json, text/event-stream"
      -H "MCP-Protocol-Version: 2026-07-28"
      -H "Mcp-Method: tools/list"
      -H "Mcp-Name: tools/list")
```

| # | Command | Expected |
|---|---------|----------|
| 1 | `curl -si -X POST "$URL" "${HDRS[@]}" -d "$BODY"` | 401 + `WWW-Authenticate: Bearer ... resource_metadata="https://$HOST/.well-known/oauth-protected-resource/mcp"` |
| 2 | same, `-H "Authorization: Bearer wrong-token"` | 401, body byte-identical to row 1 |
| 3 | same, `-H "Authorization: Bearer $MCP_AUTH_SECRET"` | 200, `result.tools[0].name == "fitness_ping"` |
| 4 | `tools/call` body with `"params":{"name":"fitness_ping","arguments":{},"_meta":{...}}` and `Mcp-Name: fitness_ping` | 200, `structuredContent == {"status":"ok","database":"connected"}` |
| 5 | `curl -s "https://$HOST/.well-known/oauth-protected-resource/mcp"` | 200, `{"resource":"https://$HOST/mcp","authorization_servers":[...],"bearer_methods_supported":["header"]}` |
| 6 | `curl -s -o /dev/null -w '%{http_code}' "https://$HOST/health"` | 200 |
| 7 | `curl -si -X POST "$URL" "${HDRS[@]}" -H "Host: wrong.example.com" -d "$BODY"` | 421 `Invalid Host header` |

**Step 2 — dedicated runtime identity and the two secrets.** Do **not** reuse the Compute Engine
default service account as the runtime identity; it typically carries `roles/editor`, and this
process holds a database credential for personal health data.

```bash
gcloud iam service-accounts create brett-run \
  --project="$PROJECT_ID" --display-name="BRETT Cloud Run runtime"

RUNTIME_SA="brett-run@${PROJECT_ID}.iam.gserviceaccount.com"

# printf, NEVER echo. `echo` appends \n, the newline becomes part of the secret
# value, and secrets.compare_digest then fails on every authenticated request
# while the value "looks right" in the console (Pitfall CR-6).
printf '%s' "$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')" \
  | gcloud secrets create brett-mcp-auth-secret --project="$PROJECT_ID" --data-file=-

printf '%s' "$NEON_DIRECT_URL" \
  | gcloud secrets create brett-database-url --project="$PROJECT_ID" --data-file=-

# Least privilege: grant per-secret, not project-wide.
for S in brett-mcp-auth-secret brett-database-url; do
  gcloud secrets add-iam-policy-binding "$S" --project="$PROJECT_ID" \
    --member="serviceAccount:${RUNTIME_SA}" \
    --role="roles/secretmanager.secretAccessor"
done

# The deploying human needs this to attach the SA to the service.
gcloud iam service-accounts add-iam-policy-binding "$RUNTIME_SA" \
  --project="$PROJECT_ID" \
  --member="user:$(gcloud config get-value account)" \
  --role="roles/iam.serviceAccountUser"
```

|----------|-------------|
| public internet → Cloud Run TLS → container | First point where a real attacker can reach the MCP endpoint; `--allow-unauthenticated` means the platform does not filter, so the MCP verifier is the only gate |
| developer machine → Neon direct connection string | A production credential is handled interactively in a shell and written into Secret Manager |
| Google Secret Manager → Cloud Run runtime service account | The only place `MCP_AUTH_SECRET` and the Neon DSN exist; the binding is the whole access-control story |
| repo working tree → Cloud Storage build bucket | `--source` uploads whatever `.gcloudignore` does not exclude |
| shell history / planning docs → git | Anything pasted into a file is committed permanently |
