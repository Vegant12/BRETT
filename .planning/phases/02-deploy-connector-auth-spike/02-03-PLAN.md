<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo → version control → Render | Everything in `render.yaml` is public to anyone with repo access and is read verbatim by the platform |
| Render dashboard → service environment | Values entered as `sync: false` or minted by `generateValue` cross into the process without touching the repo |
| public internet → deployed service | The blueprint decides which hostname and which health path are exposed unauthenticated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Information Disclosure | `render.yaml` committed secrets | mitigate | `MCP_AUTH_SECRET` uses `generateValue: true` so the value is minted server-side and never exists locally; `DATABASE_URL` uses `fromDatabase`; `test_no_secret_is_committed_as_a_literal` fails the build if any `*SECRET*`/`*KEY*`/`*TOKEN*` key ever gains a literal `value:`. Gitleaks pre-commit hook is the backstop |
| T-02-01 | Spoofing | `MCP_ALLOWED_HOSTS` value | mitigate | Blueprint sets a single explicit hostname, never `*`; `test_resource_url_and_allowed_hosts_agree` proves the resource URL's host is inside the allowlist |
| T-02-06 | Elevation of Privilege | `healthCheckPath: /health` | accept | `/health` is intentionally unauthenticated (D-04) so Render's platform check reaches it, and its body is `{status, database}` only — public by construction. Test asserts the path so it cannot be silently repointed at an authenticated route |
| T-02-03 | Information Disclosure | `MCP_RESOURCE_URL` | mitigate | Test asserts the URL ends in `/mcp` with no query string, so a token can never be smuggled into the resource identifier |
| T-02-04 | Information Disclosure | `LOG_LEVEL: INFO` in production | accept | INFO with the existing three-layer scrubber is the Phase 1 contract; DEBUG would widen the surface but is not set here |
</threat_model>
