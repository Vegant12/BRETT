1. `plan: free` → `plan: starter` (web) and `plan: free` → `plan: basic-256mb` (database)
2. Uncomment `preDeployCommand` — migrations move server-side, matching the intent already stated in `main.py`'s lifespan docstring
3. Confirm the service no longer spins down (no 15-minute idle stop)
4. Re-run Auth Verification Matrix rows 1-7 against the upgraded service BEFORE adding the connector

Claude's discovery sequence, which the connector will drive:
1. `POST /mcp` with no token → our `401` carrying `resource_metadata="https://<host>/.well-known/oauth-protected-resource/mcp"`
2. `GET` that metadata → `{"resource": "https://<host>/mcp", "authorization_servers": ["https://<project>.authkit.app"]}`
3. `GET https://<project>.authkit.app/.well-known/oauth-authorization-server` (RFC 8414)
4. CIMD or DCR client identification
5. Authorization Code + PKCE(S256) + `resource=<mcp url>`, redirect to `https://claude.ai/api/mcp/auth_callback`
6. Token endpoint → JWT with `aud` = the Resource Indicator
7. Retry `POST /mcp` with `Authorization: Bearer <jwt>` → 200

Hard timing constraints (both from primary docs): Claude allows **10 seconds** for discovery, registration, and token endpoints (30s for refresh). Render free web services stop after **15 minutes** idle and take **~1 minute** to spin up. A cold start therefore always exceeds the budget and presents as "Couldn't reach the MCP server."

`authorization_servers[0]` wins and Claude does not fall back to later entries. The SDK emits a single-entry list by construction.

Free/Pro/Max Claude plans can all add custom connectors (Customize → Connectors → "Add custom connector", with optional OAuth credentials under Advanced settings).
