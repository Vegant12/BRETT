## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `test_mcp_config_is_not_secret` was vacuous as specified**

- **Found during:** Task 2 (RED gate)
- **Issue:** The plan's `<behavior>` specified the test as "none of those values appear anywhere in `settings.secret_values()`". Written that way it **passed during RED**, before any field existed — a vacuous pass that the TDD fail-fast rule requires investigating rather than proceeding through. The root cause is structural, not a timing artifact: `secret_values()` filters on `isinstance(value, SecretStr)`, so a plain-`str` field can never appear in its output no matter what `_SECRET_FIELDS` contains. The assertion could therefore never fail for the fields it was written to guard, even after implementation.
- **Fix:** Kept the specified `secret_values()` assertions and the `MCP_AUTH_SECRET` control, and added two direct assertions per public field: that the name is absent from `_SECRET_FIELDS`, and that the runtime value `isinstance(..., str)`. `SecretStr` is not a `str` subclass (verified: `isinstance(SecretStr("x"), str)` is `False`), so the test now fails if a public field is ever redeclared as `SecretStr` — the half of the over-redaction mistake the value-only assertion structurally cannot see. Required importing `_SECRET_FIELDS` from `app.config`.
- **Files modified:** `backend/tests/test_config.py`
- **Verification:** After the change all four new tests failed at the RED gate (`4 failed, 8 passed`) and all four pass at GREEN. The test name, count, and the plan's original assertions are all preserved.
- **Committed in:** `57c8ef0` (Task 2 RED commit)
