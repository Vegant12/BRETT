<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → `POST /mcp` | Attacker-controlled `Host`, `Origin`, `Authorization`, and JSON-RPC body |
| unauthenticated → `GET /.well-known/oauth-protected-resource/mcp` | Deliberately anonymous; whatever it contains is public |
| MCP tool → database | A driver failure carries the DSN and credentials into the exception |
| catch-all mount → existing FastAPI routes | A misordered mount could silently intercept `/health` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | mounted transport (DNS rebinding) | mitigate | `test_rejects_disallowed_host` asserts `421 Invalid Host header` for `Host: wrong.example.com`, proving `TransportSecuritySettings` is live and not disabled |
| T-02-06 | Elevation of Privilege | unauthenticated bypass | mitigate | `test_rejects_unauthenticated` and `test_rejects_bad_token` assert `401` on the mounted path; `test_health_still_wins_after_mount` proves the only open route is the intended one |
| T-02-04 | Information Disclosure | 401 response body | mitigate | `test_401_leaks_nothing` asserts the exact JSON key set plus a leak loop over the configured secret, `postgresql`, `asyncpg`, `127.0.0.1`, `Traceback` |
| T-02-09 | Information Disclosure | `fitness_ping` failure path | mitigate | `test_ping_degradation_leaks_nothing` drives a real connection failure and asserts no DSN fragment reaches the tool result |
| T-02-03 | Information Disclosure | discovery metadata | mitigate | `test_protected_resource_metadata_path` asserts `resource` equals the configured URL exactly, so a token could never be smuggled into the published resource identifier |
| T-02-02 | Elevation of Privilege | token replay / confused deputy | mitigate | The metadata test pins `authorization_servers == [issuer]` — a single entry, since Claude uses `authorization_servers[0]` and never falls back |
| T-02-05 | Spoofing | timing attack | mitigate | Already enforced by the source-level guard in plan 02-02; `test_rejects_bad_token` is the behavioural complement |
</threat_model>
