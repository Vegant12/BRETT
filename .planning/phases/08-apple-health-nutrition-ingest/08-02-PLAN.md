<objective>
Remove `build_freshness`'s `provider=PROVIDER_HEVY` default and make it take explicit
`(provider, resource)` pairs, then add the two Apple Health resources D-03 specifies.

Purpose: this is RESEARCH Pitfall 7 and it is on the critical path for every health-aware
response Phase 13 will build. Today `build_freshness` silently assumes Hevy for every resource
it is asked about, so the first Apple Health resource passed to it would return Hevy's timestamp
— a plausible-looking freshness figure that is quietly wrong. D-03 further requires `activity`
and `nutrition` to be **separate** resources, because both arrive in one webhook POST but go
stale independently: a nutrition app that stops writing to HealthKit while steps keep flowing
must not report "fresh".

Output: pair-based `build_freshness`, Apple Health sync-state constants, Apple Health freshness
bundles, and tests proving the two Apple Health resources are independent of each other and of
Hevy's three.

This plan touches no Apple Health *data* — plan 08-06 is what advances the two new rows. It is
deliberately independent of every other Phase 8 plan so it can run in wave 1.
</objective>

**B. Change the function (currently lines 137-161)** to:

```python
async def build_freshness(
    session: AsyncSession,
    *,
    user_id: uuid.UUID,
    resources: Sequence[FreshnessPair],
) -> FreshnessMetadata:
    """DQ-01. One `last_synced_at` per requested (provider, resource) pair, and NOTHING else.

    There is deliberately NO `provider` default. The removed default was `PROVIDER_HEVY`, which
    meant that the first Apple Health resource passed here would have been looked up under
    provider='hevy' and returned Hevy's timestamp -- a plausible freshness figure that is quietly
    wrong, which is exactly this project's primary failure mode (RESEARCH Pitfall 7).

    The OUTPUT dict is still keyed by the bare RESOURCE name, not by a composite. Every resource
    name is unique across providers -- asserted by `test_resource_names_are_unique_across_providers`
    -- so no collision is possible, and every existing tool response keeps the exact key set it
    already advertises in `test_mcp_tool_schemas.py` and `docs/coaching-instructions.md`.

    A resource that has never synced reports `None` rather than being omitted.

    Iterated in sorted order so the map is deterministic and diffable between runs.
    """
    out: dict[str, dt.datetime | None] = {}
    for provider, resource in sorted(resources):
        state = await get_sync_state(
            session, user_id=user_id, provider=provider, resource=resource
        )
        # ONLY the last-synced timestamp is read off the row. MCP-06: the row's stored error
        # text, its run status and its two resume cursors are internal bookkeeping that must
        # never reach anything Claude can read.
        # Forbidden here: last_error, status, cursor_page, cursor_timestamp -- operator CLI only.
        out[resource] = state.last_synced_at if state is not None else None
    return FreshnessMetadata(resources=out)
```

Keep the existing MCP-06 comment block verbatim — it is the enforcement note for rule 2 of the

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `sync_state` row → analytics response → Claude | Bookkeeping internals (`last_error`, `status`, `cursor_page`, `cursor_timestamp`) live one attribute away from a value Claude reads. This boundary already exists; this plan must not widen it. |
| Provider namespace → response key namespace | Two providers now write `sync_state` rows that are projected into ONE flat dict keyed by resource name. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-06 | Spoofing | `build_freshness` provider default | mitigate | Delete the `provider: str = PROVIDER_HEVY` default. With it, an Apple Health resource looked up under `provider='hevy'` returns Hevy's timestamp — one provider's freshness presented as another's. Guarded by `test_build_freshness_has_no_provider_default` and by `test_apple_health_and_hevy_resources_resolve_per_provider`. |
| T-08-07 | Tampering | `FreshnessMetadata.resources` key collision | mitigate | Output stays keyed by the bare resource name, and `test_resource_names_are_unique_across_providers` asserts `SYNC_RESOURCES` and `APPLE_HEALTH_RESOURCES` are disjoint. A future shared name would silently overwrite one provider's timestamp with the other's. |
