<objective>
Put the ingest endpoint's credential, its own rate-limit bucket, its body-size budget, and its
deploy prerequisites in place — before the route that uses them exists.

Purpose: three separate failure modes converge here. (1) RESEARCH Pitfall 2: Health Auto Export
has **no documented retry**, so a 429 is permanent data loss — but adding the ingest path to
`EXEMPT_PREFIXES` would make an internet-reachable write path the one unbounded surface on an
`--allow-unauthenticated` Cloud Run service. The answer is a dedicated bucket, not an exemption.
(2) RESEARCH Pitfall 5 / STATE.md: `--memory=512Mi` is measured too small for JSON ingest (peak
~235 MB on a 10 MB body), and a Cloud Run OOM surfaces as a 503 with no log line. (3) The secret
must be a `SecretStr` in `_SECRET_FIELDS` or the log scrubber never learns to redact it.

Output: `health_ingest_secret` + three tuning fields in `Settings`, a second `TokenBucket`
selected by path prefix, `--memory=1Gi`, and the Secret Manager binding.

This plan deliberately does not create the route — plan 08-07 does. It is independent of every
other Phase 8 plan and runs in wave 1.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → `RateLimitMiddleware` | Cloud Run runs `--allow-unauthenticated`, so anyone can reach `/api/v1/ingest/*` before any credential is checked. The limiter is the only control that applies to an *unauthenticated* flood. |
| Internet → process memory | A request body is buffered before it can be parsed. The size cap is the boundary between "413" and "OOM 503 with no log line". |
| `Settings` → log sink | Every secret value is one careless log call away from the sink; `_SECRET_FIELDS` is the mechanism that makes redaction structural rather than a discipline. |
