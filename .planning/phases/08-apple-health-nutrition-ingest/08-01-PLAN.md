# timestamp: this row is a daily aggregate, so there is no instant to store.
local_day: Mapped[dt.date] = mapped_column(Date, nullable=False)

# (flights_climbed = 0.20163697817574894, prorated across aggregation buckets), so an INTEGER
# column truncates 59 real fragments of a day to 0 with no error anywhere (RESEARCH Finding C).
value: Mapped[Decimal] = mapped_column(Numeric(14, 4), nullable=False)

# The CANONICAL unit this row is stored in ('kcal' | 'g' | 'mg' | 'km' | 'count'), not the wire
# unit. HAE units are a per-metric USER PREFERENCE inside the phone app and change silently on
# the next export, so the stored unit is recorded rather than assumed.
units: Mapped[str] = mapped_column(String(16), nullable=False)

# How many wire datapoints were aggregated into this row. The cheapest diagnostic for Pitfall
# N-2: a sample_count that FALLS on a re-sync is a batch-split data loss, visible in one query.
sample_count: Mapped[int] = mapped_column(Integer, nullable=False)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HAE webhook payload → `health_daily_metrics` | Attacker-influencable strings (`metric`, `source`) become stored column values. Bounded here by column widths and by the allowlist in plan 08-04. |
| Stored health values → any future reader | `value` is personal health data. It must never become loggable, and column types must not silently corrupt it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `health_daily_metrics` natural key | mitigate | `source_name` is IN the 5-column unique constraint and is `NOT NULL`. Without it a Hevy-originated `active_energy` datapoint is summed into the iPhone's row and HEALTH-08 becomes unenforceable at read time (RESEARCH Finding A / Pitfall N-1). Asserted by `test_health_daily_metric_key_includes_source_name`. |
| T-08-02 | Tampering | `source_name` nullability | mitigate | `nullable=False` + `'unknown'` sentinel. PostgreSQL treats `NULL`s as distinct inside a UNIQUE constraint, so a nullable key column permits unbounded duplicate rows for every datapoint HAE sends without a `source` key — which real payloads do. |
| T-08-03 | Information Disclosure | `value` column type | mitigate | `Numeric(14,4)`, never `Float` or `Integer`. An `Integer` column silently truncates a fractional `count` metric to 0 (Finding C) — a plausible-looking number that is quietly wrong is this project's stated primary risk. |
| T-08-04 | Elevation of Privilege | `user_id` FK | mitigate | `ForeignKey("users.id", ondelete="CASCADE")` and `nullable=False`. `user_id` is never taken from the payload; the ingest resolves it server-side from `DEFAULT_USER_ID` (ASVS V4). This model provides no path for a payload-supplied tenant. |
| T-08-05 | Denial of Service | `metric` / `source_name` column widths | accept | `String(64)` / `String(128)` bound the stored length, and the metric allowlist (plan 08-04) rejects unknown names before they reach the database. An over-long `source_name` from a hostile payload raises a `DataError` inside a per-row SAVEPOINT (plan 08-06) and skips one row, not the batch. Low value target, single-user service. |
