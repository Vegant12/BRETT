by a calendar floor** — 4 qualifying sessions of that exercise AND at least 3 weeks elapsed since
the streak began, whichever requires more evidence. Pure session-count adaptivity was too
permissive for high-frequency exercises: 4 sessions of a bench press trained 3x/week is only

specifies: `PLATEAU_IMPROVEMENT_TOLERANCE = Decimal("0.02")`.

**D-07a (locked):** sessions with a `null` estimated 1RM are **skipped** — they neither extend nor

**D-07b (locked):** every plateau result reports `recent_performance`, `historical_best`, the

# Session count alone is too permissive for a high-frequency exercise: 4 sessions of a bench
# press trained 3x/week is 9-13 days, far below blueprint 21's own "3-6 weeks" floor and squarely
# inside the day-to-day fluctuation range it warns against. On live data the calendar floor blocks
# only 2 of 97 templates -- it is nearly inert today and costs nothing, and it is the guard that
# holds if the user's training frequency ever changes.
PLATEAU_MIN_QUALIFYING_SESSIONS = 4
PLATEAU_MIN_ELAPSED_DAYS = 21

# D-07. A 2% tolerance band, not a bare `>` against the strict historical maximum. ONE constant,
# named exactly as CONTEXT.md specifies, following `INSUFFICIENT_DATA_SESSION_THRESHOLD`'s form.
# Without the band, a lifter clearly trending up but bouncing within 1% of their peak -- sleep,
# RPE variance, normal session-to-session noise -- is flagged as "no progress" purely on the
# exact-max test. That is precisely the false positive blueprint 21 warns about.
PLATEAU_IMPROVEMENT_TOLERANCE = Decimal("0.02")

# PR since X" is unbounded by construction: an exercise abandoned after a peak stays plateaued
# forever. Run over all 17 months of live history the scan flags 44 of 97 templates with durations
# up to 402 days, including "Triceps Rope Pushdown: plateaued 402 days" for an exercise last
# trained 2026-05-22. Literally true under D-06, and useless as coaching. At 12 weeks: 18 of 29
# flagged at 27-75 days.
DEFAULT_PLATEAU_LOOKBACK_WEEKS = 12

_E1RM_MEAN_QUANTUM = Decimal("0.001")
_ONE = Decimal(1)


@dataclass(frozen=True, slots=True)
class PlateauScan:
    """The pure result of one streak scan. Frozen: nothing folds into it.

    Separate from ``PlateauResult`` because the Pydantic model also carries the echoed-back
    window and thresholds, which the scan itself has no opinion about.
    """

    plateaued: bool
    streak_start: dt.date | None
    qualifying_sessions: int
    recent_performance_kg: Decimal | None
    historical_best_kg: Decimal | None
    confidence: PlateauConfidence


def _plateau_confidence(qualifying_sessions: int) -> PlateauConfidence:
    """Derived from the D-06 threshold rather than invented: 4-5 low, 6-9 medium, 10+ high.

    Below D-06's floor the verdict is not "plateau" at all, so the confidence is LOW and
    ``plateaued`` is False -- a high-confidence non-plateau is not a thing this function reports.
    """
    if qualifying_sessions >= 10:
        return PlateauConfidence.HIGH
    if qualifying_sessions >= 6:
        return PlateauConfidence.MEDIUM
    return PlateauConfidence.LOW


def scan_plateau(
    series: Sequence[SessionBest], *, historical_best: Decimal | None, as_of: dt.date
) -> PlateauScan:
    """D-06 / D-07 / D-07a / D-07b as a forward state machine over the D-04 series.

    Pure and synchronous -- no session, no I/O -- so the tolerance band, the skip semantics and
    both floors are testable with no container.

    ``series`` MUST be ascending by ``local_day``. A streak read out of order is a WRONG answer,
    not a flaky one, which is why ``qualifying_set_rows`` orders by ``(template, local_day,
    workout_id, set_index)`` in SQL rather than leaving it to the caller.

    A session BREAKS the streak iff ``e1rm > running_best * (1 + PLATEAU_IMPROVEMENT_TOLERANCE)``.
    The breaking session then STARTS the new streak -- it is the most recent evidence of progress,
    so the clock runs from it.

    D-07a: sessions with ``best_e1rm_kg is None`` are SKIPPED entirely. They neither extend nor
    break. On live data 376 of 2,239 exercise-sessions (16.8%) have no qualifying set, so without
    this a deload week or a high-rep accessory day silently inflates every streak -- reading
    "rep-scheme change" as "training stalled".

    ``historical_best`` SEEDS ``running_best`` and is computed over all history strictly BEFORE
    the lookback. Seeding from ``None`` instead makes the first in-window session "improve over
    nothing", which manufactures a fake break at the window edge: on live data that moved 6
    exercises from a correct full-window plateau to a shorter, later streak start, and the
    reported duration then changes when the caller widens the lookback even though the training
    did not.

    ``as_of`` is the day the duration is measured TO -- the user's local today, not the last
    session. "You have not PR'd in 40 days" is the useful sentence; "your streak spanned 26 days"
    is not.
    """
```

    streak_start: dt.date | None = None
    streak_values: list[Decimal] = []

    for best in series:
        e1rm = best.best_e1rm_kg
        if e1rm is None:
            continue  # D-07a
        breaks = running_best is not None and e1rm > running_best * (
            _ONE + PLATEAU_IMPROVEMENT_TOLERANCE
        )
        if breaks:
            streak_start = best.local_day
            streak_values = [e1rm]
        else:
            if streak_start is None:
                streak_start = best.local_day
            streak_values.append(e1rm)
        # The running best always includes in-window sessions, so a breaking session raises the
        # bar for everything after it. Using only the pre-window history instead would let one
        # big session be beaten repeatedly by smaller ones.
        running_best = e1rm if running_best is None else max(running_best, e1rm)

    qualifying = len(streak_values)
    elapsed_days = 0 if streak_start is None else (as_of - streak_start).days
    plateaued = (
        qualifying >= PLATEAU_MIN_QUALIFYING_SESSIONS
        and elapsed_days >= PLATEAU_MIN_ELAPSED_DAYS
    )
    recent = (
        None
        if not streak_values
        else (sum(streak_values, Decimal(0)) / Decimal(len(streak_values))).quantize(
            _E1RM_MEAN_QUANTUM
        )
    )
    return PlateauScan(
        plateaued=plateaued,
        streak_start=streak_start,
        qualifying_sessions=qualifying,
        recent_performance_kg=recent,
        historical_best_kg=running_best,
        confidence=_plateau_confidence(qualifying),
    )

async def get_plateaus(
    session: AsyncSession,
    *,
    user_id: uuid.UUID,
    lookback_weeks: int = DEFAULT_PLATEAU_LOOKBACK_WEEKS,
    template_external_ids: Sequence[str] | None = None,
) -> PlateauReport:
    """PROG-03: plateau detection over a bounded, caller-configurable multi-week window.

    Takes ``lookback_weeks`` rather than a start/end pair because a plateau is always measured
    BACK FROM TODAY: "you have not PR'd in 40 days" is only meaningful relative to now, and a
    caller-supplied end date would let a stale window report a duration that stopped accruing.
    PROG-03's requirement text calls for a "configurable multi-week window" and for the window to
    be returned alongside the result -- both fields are echoed into every ``PlateauResult``.

    Session positional, everything else keyword-only, ``user_id`` with no default (ASVS V4). The
    caller owns the transaction; nothing here writes.
    """
    if lookback_weeks <= 0:
        # A caller bug, not an empty window. The message names the failure and carries no value,
        # because it will be logged (FOUND-05).
        raise ValueError("lookback_weeks must be positive")

    # Same probe idiom as `bodyweight.get_body_weight_trend`, and for the same reason:
    # `resolve_window` is the only sanctioned reader of `users.timezone`, but the anchor day
    # cannot be known until the timezone is. The probe window is never queried against.
    probe_day = local_day(utc_now(), "UTC")
    tz = (
        await resolve_window(
            session,
            user_id=user_id,
            start_day=probe_day,
            end_day=probe_day,
            snap_to_weeks=False,
        )
    ).tz
    lookback_end = local_day(utc_now(), tz)
    lookback_start = lookback_end - dt.timedelta(days=7 * lookback_weeks - 1)

    # Pitfall 4: the running best must be SEEDED from history strictly before the lookback, or
    # truncating the window manufactures a fake improvement on the first in-window session. One
    # query covering [history_start, lookback_end], split in Python -- not two queries, and not a
    # second aggregate with its own copy of the warm-up rule.
    earliest = await earliest_workout_at(session, user_id=user_id)
    history_start = lookback_start if earliest is None else local_day(earliest, tz)
    # `build_window` refuses a span above MAX_ANALYTICS_WINDOW_DAYS. Clamping here rather than
    # letting it raise means a user with more than five years of history gets a correctly seeded
    # plateau report instead of an error -- the seed loses only history older than five years,
    # which cannot be anyone's current ceiling.
    clamp_floor = lookback_end - dt.timedelta(days=MAX_ANALYTICS_WINDOW_DAYS - 1)
    history_start = max(min(history_start, lookback_start), clamp_floor)

    window = await resolve_window(
        session,
        user_id=user_id,
        start_day=history_start,
        end_day=lookback_end,
        snap_to_weeks=False,
    )
    rows = await qualifying_set_rows(
        session,
        user_id=user_id,
        window=window,
        template_external_ids=template_external_ids,
    )
    # The SAME D-04 selection PROG-01 and PROG-02 use. A second "best set" rule here is how the
    # plateau verdict and the progression series would disagree about the same day.
    bests = best_set_per_day(rows)

    seeds: dict[str, Decimal] = {}
    in_window: dict[str, list[SessionBest]] = {}
    titles: dict[str, str | None] = {}
    for (template_external_id, day), best in sorted(bests.items(), key=lambda item: item[0][1]):
        if day < lookback_start:
            if best.best_e1rm_kg is not None:
                current = seeds.get(template_external_id)
                if current is None or best.best_e1rm_kg > current:
                    seeds[template_external_id] = best.best_e1rm_kg
            continue
        # Only templates trained INSIDE the lookback are reported. An exercise last trained four
        # months ago is not plateaued, it is abandoned -- that is the whole point of D-19's bound.
        in_window.setdefault(template_external_id, []).append(best)
        titles[template_external_id] = best.title

    threshold_percent = (PLATEAU_IMPROVEMENT_TOLERANCE * Decimal(100)).quantize(_PERCENT_QUANTUM)
    exercises = [
        PlateauResult(
            exercise_template_external_id=template_external_id,
            title=titles.get(template_external_id),
            plateaued=scan.plateaued,
            # None, not 0, when not plateaued: "we did not call this a plateau" is a different
            # fact from "the plateau has lasted zero days".
            plateau_duration_days=(
                None
                if not scan.plateaued or scan.streak_start is None
                else (lookback_end - scan.streak_start).days
            ),
            qualifying_sessions_in_streak=scan.qualifying_sessions,
            recent_performance_kg=scan.recent_performance_kg,
            historical_best_kg=scan.historical_best_kg,
            confidence=scan.confidence,
            # PROG-03's requirement text: return the window AND the threshold used, alongside
            # the result. All five echoed fields exist for that sentence.
            threshold_percent=threshold_percent,
            min_sessions=PLATEAU_MIN_QUALIFYING_SESSIONS,
            min_elapsed_days=PLATEAU_MIN_ELAPSED_DAYS,
            lookback_start=lookback_start,
            lookback_end=lookback_end,
        )
        for template_external_id, scan in (
            (
                tid,
                scan_plateau(
                    series,
                    historical_best=seeds.get(tid),
                    as_of=lookback_end,
                ),
            )
            # Sorted by a stated key, never dict-iteration order.
            for tid, series in sorted(in_window.items())
        )
    ]

    return PlateauReport(
        lookback_weeks=lookback_weeks,
        lookback_start=lookback_start,
        lookback_end=lookback_end,
        exercises=exercises,
        coverage=await build_coverage(
            session, user_id=user_id, utc_start=window.utc_start, utc_end=window.utc_end
        ),
        # BOTH resources: `exercise_type` is the D-03 e1RM gate and comes from the templates
        # table, so a stale template sync silently changes every streak in this response.
        freshness=await build_freshness(
            session, user_id=user_id, resources=FRESHNESS_RESOURCES_MUSCLE
        ),
    )
```
