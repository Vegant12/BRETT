<objective>
Run the sync against the real Hevy API and answer the three questions that only real data can
answer.

Purpose: D-11 confirms the user holds a Hevy Pro subscription, so RESEARCH's assumption A7 is
true and live verification is possible. Three items are carried as open in STATE.md and
RESEARCH's Open Questions, and every one of them is undocumented by Hevy on purpose:

1. **What are Hevy's real rate limits?** An exhaustive keyword scan of the live OpenAPI found
   zero mentions of `rate limit`, `429`, `throttl`, `quota` or `retry-after`. The client already
   logs every response header matching `ratelimit`/`retry-after`; the first full sync is the only
   chance to collect them.
2. **Is dumbbell `weight_kg` per-dumbbell or combined?** Getting this wrong makes every tonnage
   and estimated-1RM figure for dumbbell work off by exactly 2×. No speculative factor may be
   applied — the raw value is stored and the semantics are documented.
3. **Are Hevy's seven unsuffixed body-measurement fields centimetres?** `waist`, `hips`,
   `abdomen` and the four limb fields carry no unit, unlike their seven `*_cm` siblings.

Output: `docs/hevy-api-observations.md`, and ROADMAP success criteria 1-3 demonstrated against
real data rather than fixtures.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hevy account → local `.env` | A real, long-lived credential enters the working tree's environment |
| live sync → repository | Real personal health data is now in the database and in captured logs |
| observations file → git history | Anything written here is permanent and, if the repo is ever shared, public |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-49 | Information Disclosure | the API key in `.env` | mitigate | `.env` is gitignored (asserted with `git check-ignore`); the key is never echoed — the sanity check prints a boolean, not the value; the key is never pasted into chat, a commit message, or any file under `docs/` or `.planning/`. `_SECRET_FIELDS` already scrubs it from every log line. |
| T-03-50 | Information Disclosure | captured sync logs | mitigate | Logs are written to `/tmp/brett-live/`, outside the repository, and are never added to git. They contain workout titles, which the redaction pipeline does not treat as secrets because they are legitimate application data. |
| T-03-51 | Information Disclosure | `docs/hevy-api-observations.md` | mitigate | Explicit content rules: structural facts only, one dumbbell exercise and one or two measurement values, no dated session list. Two grep-based acceptance criteria assert no UUID and no `api-key`-shaped string is present. |
| T-03-52 | Tampering | speculative dumbbell correction factor | mitigate | The raw `weight_kg` is stored unmodified; the semantics are documented rather than compensated for. Applying a 2× factor on a guess would corrupt every historical tonnage figure irreversibly. |
| T-03-53 | Denial of Service | hitting an unknown rate limit during a first full sync | mitigate | `wait_exponential_jitter` + `stop_after_attempt(5)` are already in the client, and per-page commit with a resume cursor means a rate-limit stop is recoverable by simply re-running the command. |
