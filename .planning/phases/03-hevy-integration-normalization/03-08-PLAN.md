<objective>
Sync Hevy body measurements into the single `body_measurements` table, keyed on the calendar
date.

Purpose: HEVY-07, and it is what unlocks BODY-01/BODY-02 in Phase 5 without waiting for
HealthKit. Two live-API facts settle the design and both contradict earlier assumptions: Hevy's
`/v1/body_measurements` returns **one object per calendar date carrying all 17 metrics**, and it
has **no `id` field at all** — the date *is* the identity, confirmed by the sibling
`GET/PUT /v1/body_measurements/{date}` endpoints and a POST that 409s if an entry already exists
for that date. D-07's fallback assumed a per-metric key; the correct natural key is
`(user_id, source, measured_on)` for the whole row.

Output: `backend/app/integrations/hevy/body.py` and its integration suite.

Module docstring:
```python
"""Body-measurement sync (HEVY-07, D-05, D-06, D-07-corrected).

Three live-API facts shape everything here, and all three contradict what the blueprint
assumed:

* There is NO id field on a body measurement. The calendar DATE is the identity -- confirmed
  by the sibling endpoints `GET/PUT /v1/body_measurements/{date}` and a POST that returns 409
  if an entry already exists for that date. The natural key is therefore
  `(user_id, source, measured_on)` for the whole ROW; D-07's per-metric fallback was the wrong
  granularity.
* ONE row carries all 17 metrics. It is not one row per metric.
* `/v1/body_measurements` answers **404 "Page not found"** for an out-of-range page, where
  `/v1/workouts` answers 400. Treating that 404 as fatal would mark a run failed after it had
  already fetched everything (Pitfall 5). The client turns it into `None`; this module treats
  `None` as the terminator.

Hevy leaves seven fields without a unit suffix (`abdomen`, `waist`, `hips`, `left_thigh`,
`right_thigh`, `left_calf`, `right_calf`). They are renamed to `*_cm` on the way in, for
consistency with the other seven and with blueprint §41. Centimetres is an ASSUMPTION Hevy does
not document -- it is flagged for confirmation against the app on the first live sync.
"""
```

**`async def upsert_body_measurement(session, *, user_id: uuid.UUID, measurement: HevyBodyMeasurement) -> None`**
```python
    metrics = {
        column: getattr(measurement, wire) for wire, column in _WIRE_TO_COLUMN.items()
    }
    stmt = pg_insert(BodyMeasurement).values(
        id=uuid.uuid4(), user_id=user_id, source=SOURCE_HEVY,
        # No external_id: this endpoint has no id to store. The column exists for a future
        # provider that does have one.
        external_id=None,
        measured_on=measurement.date,
        **metrics,
    )
    # EVERY metric is written on conflict, including the ones that are now None. Hevy's own
    # PUT documents "all fields are overwritten; omitted fields are set to null", so the local
    # upsert mirrors row-replacement semantics: a metric the user deleted upstream must
    # disappear locally rather than linger as a stale value in a weight trend.
    stmt = stmt.on_conflict_do_update(
        constraint="uq_body_measurements_user_source_measured_on",
        set_={column: getattr(stmt.excluded, column) for column in _WIRE_TO_COLUMN.values()},
    )
    await session.execute(stmt)
```

**`async def sync_body_measurements(client, sessionmaker, *, user_id) -> BodyMeasurementSyncResult`**
Mirror `sync_workouts`:
1. Own transaction: `ensure_sync_state(..., resource=RESOURCE_BODY_MEASUREMENTS)`,
   `start_page = state.cursor_page or 1`, `mark_running`, commit. Log
   `hevy_body_sync_started`.
2. `try:` / `except Exception as exc:` → fresh session, `record_sync_error`, commit, log
   `hevy_body_sync_failed` with `reason=type(exc).__name__`, re-raise. Cursors untouched.
3. Page loop:
   ```python
   page = start_page
   while True:
       payload = await client.get_body_measurements(page=page)
       if payload is None:
           # Pitfall 5: a 404 here means "past the last page", not a failure.
           log.info("hevy_body_pagination_terminated", page=page)
           break
       pages_fetched += 1
       async with sessionmaker() as session:
           for measurement in payload.body_measurements:
               try:
                   async with session.begin_nested():
                       await upsert_body_measurement(
                           session, user_id=user_id, measurement=measurement)
               except SQLAlchemyError as exc:
                   # Class name only: str(DataError) renders the bound parameters, which
                   # here are this person's body-composition numbers (T-03-34).
                   log.warning("hevy_body_measurement_skipped",
                               measured_on=measurement.date.isoformat(),
                               reason=type(exc).__name__)
               else:
                   rows_upserted += 1
           await advance_cursor_page(session, ..., cursor_page=page + 1)
           await session.commit()
       if not payload.body_measurements or page >= payload.page_count:
           break
       page += 1
   ```
4. Close: `complete_sync(..., last_synced_at=utc_now(), cursor_page=None)` + commit; log
   `hevy_body_sync_completed` with `pages` and `rows`.

Never log a metric value. `measured_on` is fine (it is a date, not a body composition figure);
`weight_kg` is not.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Hevy response → `body_measurements` | Personal health data (weight, body fat, circumferences) enters persistent storage |
| sync process → log sink | Lifecycle logs must not carry the values they are describing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-33 | Information Disclosure | sync lifecycle logging | mitigate | Logs emit page numbers, row counts and ISO dates only. `test_no_metric_value_reaches_the_log_stream` asserts the fixture's weight, lean-mass and body-fat values are absent from the rendered stream (ASVS V8, blueprint §44). |
| T-03-34 | Information Disclosure | skipped-row logging | mitigate | The quarantine log emits `measured_on` and `type(exc).__name__` only; `str(DataError)` would render the bound parameters, i.e. the measurements themselves. |
| T-03-35 | Tampering | stale metric after upstream deletion | mitigate | `on_conflict_do_update` writes **every** metric column including `None`, mirroring Hevy's documented PUT semantics, so a metric cleared upstream is cleared locally. Asserted by `test_metric_cleared_upstream_is_cleared_locally`. |
| T-03-36 | Denial of Service | 404 misread as a failure | mitigate | `HevyPageNotFound` is excluded from `RETRYABLE_EXCEPTIONS` and the client converts it to `None`; `test_404_consumes_no_retry_budget` asserts exactly one call. |
| T-03-37 | Elevation of Privilege | cross-user measurements | mitigate | `user_id` is a required keyword argument and part of the unique constraint; every read and write filters on it. |
</threat_model>
