Purpose: ROADMAP success criterion 5 needs each data source to report *a readable*
`last_synced_at` — that is a single `status()` call, not three ad-hoc queries. And this phase

logged before `configure_logging` would write an unredacted line, and the very first thing it
would log is a Hevy request.

mock-Hevy → PostgreSQL → normalized-state test that ties the whole phase together.

Module docstring:
```python
"""HevySyncService: the one place that decides WHAT to sync and in WHICH order (HEVY-09).

Composition only. Every transaction boundary, every checkpoint write and every retry already
lives in the four drivers this class calls; adding a second layer of transaction handling here
would make it impossible to reason about which one committed.

Order is deliberate: exercise templates first, then workouts, then body measurements. Nothing
strictly requires it -- D-03 guarantees a workout syncs whether or not its template exists --
but syncing templates first means a fresh database is never briefly in the state where every
exercise is unmapped, which is the state that makes Phase 4's output look broken.

The service borrows a sessionmaker; it never builds an engine. `app/mcp/context.py` documents
why a second engine in a second component is a bug rather than an inconvenience.
"""
```

```python
log = structlog.get_logger()

SyncMode = Literal["auto", "full", "incremental"]


@dataclass(frozen=True, slots=True)
class ResourceStatus:
    resource: str
    last_synced_at: dt.datetime | None
    status: str
    last_error: str | None
    cursor_page: int | None
    cursor_timestamp: dt.datetime | None


@dataclass(frozen=True, slots=True)
class SyncReport:
    mode: SyncMode
    templates: TemplateSyncResult | None = None
    workouts_full: WorkoutSyncResult | None = None
    workouts_incremental: EventSyncResult | None = None
    body: BodyMeasurementSyncResult | None = None


class HevySyncService:
    def __init__(
        self,
        client: HevyClient,
        sessionmaker: async_sessionmaker[AsyncSession],
        *,
        user_id: uuid.UUID,
    ) -> None: ...

    async def resolve_mode(self, requested: SyncMode) -> Literal["full", "incremental"]:
        """`auto` means: incremental if a full workout sync has ever completed, else full.

        The check is `last_synced_at is not None` on the `workouts` resource, NOT
        `cursor_timestamp` -- the events cursor only exists after the FIRST incremental run,
        so keying on it would make every second run a full re-import.
        """

    async def sync_templates(self) -> TemplateSyncResult: ...
    async def sync_body(self) -> BodyMeasurementSyncResult: ...

    async def sync_all(self, *, mode: SyncMode = "auto") -> SyncReport:
        """Templates -> workouts (full or incremental) -> body measurements.

        No try/except: each driver already records its own failure into `sync_state` before
        re-raising, and swallowing it here would report a green sync over a resource that
        never ran. Resources completed before the failure keep their `last_synced_at`, which
        is exactly what HEVY-08 asks for.
        """

    async def status(self) -> list[ResourceStatus]:
        """HEVY-09, in one call.

        Returns an entry for every member of SYNC_RESOURCES, including ones that have never
        run -- "never synced" is the answer to "when was this last synced", and omitting the
        row would make it indistinguishable from "the resource does not exist".
        """
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell → process | Command-line arguments and environment enter the process |
| process start → first log line | Anything logged before `configure_logging` bypasses all three redaction layers |
| service → operator stdout/stderr | Failure messages are printed outside the redaction pipeline |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-44 | Information Disclosure | CLI bootstrap order | mitigate | `get_settings()` then `configure_logging(settings)` then anything else, mirroring `app/main.py`. `test_configure_logging_precedes_every_log_call` statically asserts no `log.` or `make_engine` appears earlier in the file. |
| T-03-45 | Information Disclosure | CLI error output on stderr | mitigate | Only `exc.safe_message` or the exception class name is printed; `str(exc)` is banned and asserted absent. `build_hevy_client`'s `RuntimeError` names the ENV VAR (`HEVY_API_KEY`) and never its value. |
| T-03-46 | Information Disclosure | sync lifecycle logs | mitigate | `hevy_sync_all_started/completed` carry mode and counts only. `test_no_health_data_reaches_the_log_stream` asserts workout titles and body-composition values are absent from the rendered stream across a full run. |
| T-03-47 | Denial of Service | connection leak on failure | mitigate | `try/finally: await engine.dispose()` and `async with build_hevy_client(...)` guarantee both the pool and the HTTP client close on every exit path. |
| T-03-48 | Elevation of Privilege | `--user-id` accepting an arbitrary uuid | accept | Single-user personal deployment; the CLI is only reachable by someone who already has shell access to the deployment and the database credentials. Revisit if the sync trigger ever becomes an HTTP route. |
