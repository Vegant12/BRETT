## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| real exercise inventory → committed repo | Template ids and titles from a real account enter git |
| curated data → Phase 4 analytics | A wrong curation produces confident, wrong per-muscle volume |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-54 | Information Disclosure | curated ids and titles in git | accept | Exercise template ids and titles are Hevy's public exercise library plus, at most, the names of custom exercises. They carry no dates, no loads, and no body-composition data — unlike the workout history, which is never committed. |
| T-03-55 | Tampering | a curated entry that resolves to nothing | mitigate | `CURATED_BY_TEMPLATE_ID` replaces the mechanical translation entirely, so an empty entry would silently delete a mapping. `test_curated_template_ids_resolve_to_something` fails the fast suite on that. |
| T-03-56 | Tampering | contradictory classification | mitigate | `test_curated_and_deliberately_unmapped_are_disjoint` prevents an id from being both curated and deliberately excluded. |
| T-03-57 | Denial of Service | `mapping-gaps` used as a CI gate | mitigate | The command always exits 0 and the behaviour is locked by `test_mapping_gaps_is_not_a_gate`; D-03 guarantees an unmapped exercise never blocks anything. |
| T-03-58 | Tampering | `full_body` fan-out | mitigate | `DELIBERATELY_UNMAPPED` documents the exclusion rather than expanding `full_body` to all 19 groups, which would inflate every Phase 4 per-muscle figure. |
</threat_model>
