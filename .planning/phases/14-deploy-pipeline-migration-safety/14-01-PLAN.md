# Alembic writes its `INFO  [alembic.runtime.migration] ...` banner to stderr, but a
# misconfigured logging handler could put it on stdout; a banner word must never be
# mistaken for a revision id.
_LOG_LEVEL_TOKENS = frozenset({"INFO", "WARNING", "ERROR", "DEBUG", "CRITICAL"})

# `0006 (head)` -> `0006`. Revision ids in this repo are zero-padded numerals, but the
# pattern stays generic so a future hash-style id still parses.
_REVISION_TOKEN = re.compile(r"^([0-9A-Za-z_]+)(?:\s|$)")

AlembicRunner = Callable[..., subprocess.CompletedProcess[str]]


@dataclass(frozen=True)
class PreflightResult:
    ok: bool
    current: frozenset[str]
    heads: frozenset[str]
    detail: str

6. `def check_at_head(run: AlembicRunner, *, database_url: str = "") -> PreflightResult` — the
   predicate. Steps, in order:
   - `current = run("current")`; if `current.returncode != 0`, return
     `PreflightResult(ok=False, current=frozenset(), heads=frozenset(), detail=redact("alembic current failed: " + current.stdout + current.stderr, database_url))`
   - `heads = run("heads")`; same non-zero handling with `"alembic heads failed: "`.
   - `current_revs = parse_revisions(current.stdout)`, `head_revs = parse_revisions(heads.stdout)`
   - `ok = bool(head_revs) and current_revs == head_revs` — the `bool(head_revs)` guard is
     load-bearing: with no migrations resolvable, `set() == set()` would report a stale database
     as in sync.
   - `detail` on success: `f"at head: {sorted(head_revs)}"`. On failure:

Run `alembic upgrade head` against this database and re-run the pre-flight."`
   - Revision ids are NOT secrets — print them. The DSN is, and never appears in `detail` except
     through `redact`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| production DSN → operator terminal / CI log | The pre-flight receives the production `DATABASE_URL` and prints diagnostics; anything it emits is captured in a deploy log that outlives the deploy |
| pre-flight process → production database | The predicate opens a connection to the production database (read-only: `alembic current` reads `alembic_version`) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Information disclosure | `migration_preflight.redact` / `check_at_head` error paths | mitigate | Every string derived from alembic stdout/stderr passes through `redact(text, database_url)`, which replaces the full DSN and its password longest-first with `REDACTED` (mirroring `Settings.secret_values`'s documented ordering rule). `main()` never prints `database_url` directly. Asserted by `test_preflight_module_entrypoint_exits_nonzero_on_drift_without_leaking_the_dsn` and by the `redact` unit tests |
| T-14-05 | Repudiation | deploy log has no record of which revision was verified | mitigate | `PreflightResult.detail` names the concrete `current` and `heads` revision id sets on both the success and the failure path, and `main()` prints it. Revision ids are not secrets; the DSN is and is excluded |
| T-14-07 | Tampering | `check_at_head` reading an unresolvable migrations tree as "in sync" | mitigate | `ok = bool(head_revs) and current_revs == head_revs` — an empty head set (broken `script_location`, wrong cwd, alembic not installed) fails closed rather than passing a stale database. Covered by the empty-output unit test |
| T-14-08 | Denial of service | `subprocess.run` with no timeout hangs the deploy if the database is unreachable | accept | asyncpg/psycopg connection attempts fail fast with `ConnectionRefusedError`; a hung deploy is loud, local, and interruptible by the operator, whereas a wrong timeout would abort a legitimately slow migration mid-apply — the worse failure |
