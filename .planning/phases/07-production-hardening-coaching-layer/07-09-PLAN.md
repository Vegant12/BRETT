## Why this is a DEPLOY procedure, not a `gcloud secrets` procedure
Cloud Run resolves `--set-secrets=NAME=secret:latest` into an environment variable AT INSTANCE
START, not per request. Adding a version therefore has zero effect until a new revision serves
traffic. `scripts/deploy-cloud-run.sh` is the mechanism that makes a rotation take effect.

## Why the mode has to be flipped
`deploy/cloud-run.env.yaml` sets `MCP_AUTH_MODE: "authkit"`, and `build_token_verifier`
(`backend/app/mcp/auth.py:117-141`) returns `AuthKitJWTVerifier` in that mode —
`StaticTokenVerifier` is never constructed. A bearer request carrying the NEW secret gets 401,
identically to the old one, so "new token succeeds" is not observable without a temporary flip
to `static`. That flip is the same lever the file already documents as the WorkOS-outage
rollback path, exercised here for the first time.

## Does rotation break the live connector?
No, and the reason is worth stating plainly rather than implying risk: in the steady state
(`authkit`), Claude authenticates with a WorkOS-issued JWT and `MCP_AUTH_SECRET` is not in the
request path at all. Rotating it is invisible to the connector. The only window of exposure is
the deliberate `static` interval this procedure opens and closes.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Secret Manager → Cloud Run environment | `MCP_AUTH_SECRET` resolves into an environment variable at instance start; a wrong version means a service nobody can authenticate to, or one anyone with the old token can |
| Operator shell → transcript / files / git | The old and new token values pass through this plan; every representation of them is a leak channel |
| Internet → `/mcp` during the static window | For the duration of the flip, a single long-lived bearer token is the whole of authentication |
| Claude client ↔ WorkOS | Two redeploys occur; consent must survive both |

| T-07-47 | Elevation of Privilege (ASVS V14) | Service left in `static` mode | mitigate | The flip-back is a mandatory verified step with two independent acceptance criteria: `gcloud run services describe` must report `authkit` read back from the LIVE service, and `git diff --quiet deploy/cloud-run.env.yaml` must exit 0. The runbook's "Known limitations" states that nothing else alerts on this. |
