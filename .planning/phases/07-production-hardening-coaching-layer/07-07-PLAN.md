## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.env` on the developer machine → Secret Manager | The Hevy API key crosses from a gitignored local file into GCP; every intermediate representation (terminal, shell history, process table, transcript) is a leak channel |
| Cloud Scheduler → Run Admin API | An OAuth-token-authenticated call that starts a job which can write to the production database |
| Cloud Run Job → Hevy API and Neon | The job holds both a third-party API key and a production database credential in its environment |
| Cloud Logging → committed runbook | Log output copied into `docs/` is public in git forever |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-33 | Information Disclosure (ASVS V6/V14) | Moving `HEVY_API_KEY` into Secret Manager | mitigate | The value is piped from `.env` to `gcloud … --data-file=-` through a Python heredoc that writes only to stdout. `--data="…"` is explicitly forbidden (process table + shell history), `gcloud secrets versions access` is forbidden, and an acceptance criterion states the value must not appear in any transcript, file or history entry. If `.env` lacks the key the plan stops rather than prompting for it in conversation. |
| T-07-34 | Elevation of Privilege (ASVS V4) | IAM scope | mitigate | `roles/secretmanager.secretAccessor` is bound on the individual secret, not project-wide, and `roles/run.invoker` is bound on the individual job, not project-wide. Both bindings are read back with `get-iam-policy` rather than assumed (07-RESEARCH.md A1). |
| T-07-35 | Information Disclosure (ASVS V7) | Job logs | mitigate | Task 2 step 6 scans the retrieved log window for `postgresql://`, an `api-key` header value and the Hevy key, and treats any hit as a FOUND-05 regression to raise rather than note.
