```python
@contextlib.asynccontextmanager
async def _mcp_over(engine: AsyncEngine) -> AsyncIterator[None]:
    """Point `app.state.sessionmaker` at the container the sync just committed to.

    Entering `Client(mcp)` runs `mcp_lifespan`, which reads `app.state.sessionmaker`
    (app/mcp/context.py:41). Without this the tool opens a session against whatever
    DATABASE_URL points at -- a different database, which would answer every question
    with zeros and look like a passing test of an empty window.
    """
    from app.main import app

    preexisting = getattr(app.state, "sessionmaker", None)
    app.state.sessionmaker = async_sessionmaker(engine, expire_on_commit=False, autoflush=False)
    try:
        yield
    finally:
        if preexisting is not None:
            app.state.sessionmaker = preexisting
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude (model) → MCP tool arguments | Tool arguments are model-generated and therefore untrusted structurally: a wrong type or a missing required field must be rejected, not coerced |
| Mocked Hevy API → sync → Postgres | Fixture JSON crosses the wire schema boundary; the composition test must exercise the real parsing path, not bypass it |
| Tool result → Claude | Any tool exception's `str()` reaches Claude verbatim in `mcp 2.0.0`, which is why `@safe_tool` wraps all twelve tools |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | Tampering (ASVS V5) | MCP tool argument validation | mitigate | Two new tests assert that a wrong-typed argument and a missing required argument are both rejected by `FuncMetadata.call_fn_with_arg_validation` before the tool body runs, producing `is_error=True` and `structured_content is None` — so no database work happens on an invalid call. |
| T-07-08 | Information Disclosure (ASVS V7) | The composition test's MCP call | mitigate | The test calls the tool through `Client(mcp)`, i.e. through the registered `@safe_tool` wrapper, so it cannot pass by bypassing the layer that stops a DSN or traceback reaching Claude. The existing parametrized DSN-leak test in `test_mcp_tools.py` remains the primary guard and stays green in the full suite. |
| T-07-09 | Information Disclosure (ASVS V4) | Composition test queries | mitigate | Every analytics call in the new module passes `user_id=DEFAULT_USER_ID` explicitly; no unscoped query is introduced. `test_analytics_isolation.py` and `test_mcp_isolation.py` remain the static guards and must stay green. |
| T-07-10 | Tampering / data corruption | Committed rows outliving the test | mitigate | `sync_all()` commits and the Postgres container is session-scoped, so every test body is wrapped in `try/finally: await _cleanup(maker)` with the compensating `DELETE` set copied from `test_hevy_end_to_end.py`.
