**Bucket-replacement helper** — the seam plan 07-01's middleware provides:

```python
def _drain(client: TestClient, *, capacity: int = 2) -> None:
    """Replace the live bucket with a tiny, frozen-clock one and empty it.

    `app.state.rate_limit_bucket` is the single live bucket object and the middleware
    reads it per request, so swapping it here takes effect without rebuilding the
    middleware stack. The clock is frozen rather than advanced: a bucket that could
    refill mid-test would make the assertions racy, and there is no sleep anywhere
    in this module.
    """
    bucket = TokenBucket(capacity=capacity, refill_per_second=0.5, clock=lambda: 1_000.0)
    for _ in range(capacity):
        assert bucket.take() is None
    client.app.state.rate_limit_bucket = bucket
```

@pytest.mark.integration
def test_the_429_leaks_nothing(client: TestClient) -> None:
    """T-07-02: the rejection body is one field and nothing else.

    The exact key set is asserted, not merely the absence of known-bad strings.
    Unlike the 401, whose envelope the MCP SDK owns and holds still, this body is
    entirely ours and nothing external stops it growing a field -- so the failure
    worth guarding is a future edit that helpfully starts echoing the presented
    credential, the configured issuer, or an exception detail on an endpoint anyone
    on the internet can make emit it. A substring check would not notice a new
    field; a key-set check cannot miss it.
    """
    _drain(client)
    response = client.post("/mcp", json=LIST_BODY, headers={**MCP_HDRS, **AUTH})

    assert response.status_code == 429, (...)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → ASGI middleware stack | The service is `--allow-unauthenticated`; requests reach the limiter before any credential is examined |
| Limiter → MCP sub-app auth chain | The limiter must not weaken, bypass or reorder `AuthenticationMiddleware` / `RequireAuthMiddleware` |
| 429 response → anonymous caller | Anyone can make this body appear; it is a public output channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02 | Information Disclosure (ASVS V7) | The 429 body | mitigate | `test_the_429_leaks_nothing` asserts the EXACT key set `{"error"}` plus a leak-marker loop over the test credential, `postgresql`, `asyncpg`, `127.0.0.1` and `Traceback` — the same discipline as the shipped `test_401_leaks_nothing`. |
| T-07-24 | Elevation of Privilege (ASVS V2) | Middleware ordering vs auth | mitigate | `test_the_limiter_runs_before_auth` proves the limiter fires ahead of `RequireAuthMiddleware` (unauthenticated flood → 429), while `uv run pytest backend/tests/test_mcp_auth.py -m integration` proves the 401 envelope with `resource_metadata=` is byte-unchanged. The limiter bounds, it does not authorise. |
| T-07-04 | Denial of Service, self-inflicted (ASVS V11) | Health probe, RFC 9728 discovery | mitigate | `test_health_is_never_rate_limited` and `test_discovery_document_is_never_rate_limited` both run against a DRAINED bucket, so the exemption is proven under the exact condition that would otherwise break Cloud Run's probe and Claude's 10-second connector discovery. |
| T-07-25 | Denial of Service | False-positive throttling of legitimate traffic | mitigate | `test_an_authenticated_request_under_the_limit_still_succeeds` runs against the DEFAULT bucket (30 burst / 30 per minute), so a mistuned default that throttles a normal call fails the suite. Real per-turn call counts are measured during the plan 07-10 UAT and any 429 observed there is treated as a tuning bug. |
| T-07-26 | Tampering | Streaming responses broken by the middleware | mitigate | The integration tests drive the real `/mcp` endpoint, which answers `text/event-stream`; a `BaseHTTPMiddleware`-shaped regression would hang or truncate these tests. `grep -c BaseHTTPMiddleware backend/app/main.py` returning `0` is an acceptance criterion. |
</threat_model>
