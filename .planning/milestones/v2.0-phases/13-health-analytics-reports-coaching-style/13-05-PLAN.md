Fixture choice, load-bearing: use `golden_workout` (flush-and-rollback, same session) for these
analytics tests, NEVER `committed_history`. `test_mcp_tools.py`'s docstring explains the inverse:
a tool driven through `Client(mcp)` opens its own transaction and cannot see uncommitted rows,
which is why THAT suite needs `committed_history`. An analytics function called directly with
the fixture's own session sees the flushed rows, and rollback teardown is free.

Anchor idiom used by the code under test (bodyweight.py:198-208):

    probe_day = local_day(utc_now(), "UTC")
    tz = (await resolve_window(...)).tz          # 'Asia/Jakarta' for the seeded default user
    anchor = local_day(utc_now(), tz)

So a test must seed relative to `local_day(utc_now(), "Asia/Jakarta")`, not to `dt.date.today()`
and not to a literal.

Registry facts the assertions depend on (backend/app/integrations/health_auto_export/registry.py):
`step_count` → unit `count`; `dietary_energy` → `kcal`; `sodium` → `mg`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Test fixture → shared container | Seeded rows must not survive into another test's assertions |
| Test tenant scoping | The single seeded production user cannot, alone, detect a missing `user_id` predicate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-20 | Information Disclosure | Cross-tenant read | mitigate | Two dedicated second-user tests (one per entry-point family) assert a second user's rows never appear. This is the only mechanism that can catch a dropped tenant predicate in a single-user product. |
| T-13-21 | Tampering | Test isolation | mitigate | `golden_workout` flushes and rolls back, so no seeded row escapes its test. `committed_history` is deliberately NOT used here and the acceptance criteria grep for its absence. |

The acceptance criteria grep for zero hard-coded `dt.date(20..)` literals, which is the failure `bodyweight.py`'s docstring records as passing for the wrong reason. |
