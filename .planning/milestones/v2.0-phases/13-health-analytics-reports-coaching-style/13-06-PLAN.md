<objective>
Expose HEALTH-12 and NUTR-06 as two dedicated MCP tools.

Purpose: D-07 is explicit — activity gets its own tool, because "a bare 'how active have I
been?' question needs a direct answer path, not only a full report call" — extending rather than
breaking the one-tool-per-analytics-slice pattern already used for volume, frequency,
body-weight trend and body-measurement trend. NUTR-06 asks the same for nutrition, and D-08
fixes its shape: ONE response with all seven values, no metric-selector parameter, unlike
`fitness_get_body_measurement_trend`'s enum selector — nutrition values are asked about together.

This plan also pays the registry tax every new tool in this repo owes: five separate guards fail
the moment a tool is registered and any one of them is not updated. That is by design —
`test_mcp_isolation.py`'s own failure message says "all three, so a new tool cannot ship
unguarded and unnoticed."

Output: two response models, one tool module, two registrations, five guard updates, two
coaching-doc table rows, and two measured budgets.
