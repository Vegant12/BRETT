Purpose: three pitfalls converge on this one file.

**Pitfall 1 — route registration order.** `app.mount("/", mcp_app)` in `main.py` is a catch-all and
is registered LAST on purpose. A route added *below* it is dead in production while every unit
test that builds its own app passes. `test_secret_redaction.py:62-78` already had to re-append the
mount after adding a route at test time — that is the existing evidence, and this route needs the
same care plus a test that actually resolves over HTTP.

**Pitfall 3 — a FastAPI route inherits zero auth.** The MCP SDK's `RequireAuthMiddleware` wraps
only `mcp_app`. A new FastAPI route on an `--allow-unauthenticated` Cloud Run service is an open
write path unless it checks the credential itself.

**Pitfall 5 — 413 before parse.** The size cap has to apply before `model_validate_json`, or the
instance OOMs and Cloud Run answers 503 with no application log line to explain it.

Output: the route, its registration, its HTTP-level tests, and the criterion-#4 isolation proof.

**The handler:**

```python
@router.post("/health-auto-export")
async def ingest_health_auto_export(request: Request) -> JSONResponse:
    settings = get_settings()

    # 1. CREDENTIAL FIRST -- before a single byte of body is read. Fails closed on an unset
    #    secret. The log line says only that a rejection happened: never the presented value,
    #    never which of the three reasons applied. Success criterion #2 requires exactly this.
    secret = settings.health_ingest_secret
    if secret is None or not verify_bearer(
        request.headers.get("authorization"), secret.get_secret_value()
    ):
        log.warning("health_ingest_unauthorized")
        return JSONResponse(status_code=401, content=_UNAUTHORIZED_BODY)

    # 2. SIZE CAP -- before the parse. The declared length is checked first because it costs
    #    nothing, then the stream is capped as it is read, because Content-Length is optional
    #    and attacker-controlled. RESEARCH Pitfall 5: without this the instance OOMs and Cloud
    #    Run answers 503 with no application log line.
    cap = settings.ingest_max_body_bytes
    declared = request.headers.get("content-length")
    if declared is not None and declared.isdigit() and int(declared) > cap:
        log.warning("health_ingest_payload_too_large", declared_bytes=int(declared), cap=cap)
        return JSONResponse(status_code=413, content=_TOO_LARGE_BODY)

    body = bytearray()
    async for chunk in request.stream():
        body.extend(chunk)
        if len(body) > cap:
            log.warning("health_ingest_payload_too_large", read_bytes=len(body), cap=cap)
            return JSONResponse(status_code=413, content=_TOO_LARGE_BODY)

    # 3. PARSE -- inside the quarantine boundary. Never `str(exc)`: a pydantic ValidationError
    #    renders `input_value=...`, i.e. this person's calorie counts, into a log line.
    try:
        payload = HAEPayload.model_validate_json(bytes(body))
    except ValidationError as exc:
        log.warning("health_ingest_payload_rejected", reason=type(exc).__name__)
        return JSONResponse(status_code=400, content=_INVALID_PAYLOAD_BODY)

    # 4. INGEST. `user_id` is resolved SERVER-SIDE (ASVS V4). Health Auto Export cannot supply a
    #    tenant and must not be able to.
    result = await ingest_payload(
        request.app.state.sessionmaker, user_id=DEFAULT_USER_ID, payload=payload
    )

    # 5. COUNTS ONLY (ASVS V8). Never a value, never a metric's stored quantity.
    return JSONResponse(
        status_code=202,
        content={
            "status": "accepted",
            "rows_upserted": result.rows_upserted,
            "rows_skipped": result.rows_skipped,
            "datapoints_seen": result.datapoints_seen,
            "metrics_unrecognized": result.metrics_unrecognized,
        },
    )
```
